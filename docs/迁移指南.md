# 记忆库迁移指南（老用户：md → 主题库）

> 适用范围：**老用户**（`~/.dsh/memory/` 下已有旧版 md 记忆，主题库为空或不存在）。
> 迁移只做一件事：把旧 md 的正文导入 SQLite 主题库（`.memtopic/mem.db`），让插件的新记忆协议（`memory_search` 检索、`memory_note` 会话笔记；`memory_write` / `memory_dream_patch` 仅 dream 整合可用）跑起来。
> **md 不会被删除、不会被改写**；迁移可回滚、可重复执行。
>
> **已经是 4.0.x（含 4.0.1）？** 不用做本文的 md 迁移，直接看 **[第 6 节「从 4.0.1 升级到 4.5」](#6-从-401-升级到-45)**——重跑安装命令 + 重启即可，无需迁移数据。

---

## 0. 先检测（只读，不改任何东西）

三种入口任选其一（见第 1 节），推荐先跑一次检测：

```bash
node <插件目录>/memtopic/src/migrate.mjs --detect
```

输出会明确告诉你三件事：

1. **旧版 md 有多少**：sessions / knowledge / projects / tools 各多少文件、多少句；
   `global.md` / `index.md` 属"人工稳定层"，**不导入**（可直接用编辑器改）。
2. **主题库状态**：是否存在、已有多少主题/句子、`schema_version`。
3. **建议动作**：
   - `⚠ 检测到旧版 md 记忆，需要迁移` → 看第 1 节执行迁移；
   - `✓ 已迁移（主题库已有数据，无需操作）` → 什么都不用做，旧 md 保留是正常的；
   - `○ 空库（没有可迁移的 md）` → 直接用插件即可。

检测还会报告 **DSH 是否正在运行**（依据：进程扫描 / 锁与 pid 文件，逐条列出）。迁移要求 DSH 已完全退出。

## 1. 三种迁移入口

### 入口 A：重跑安装器（推荐）

老用户重跑同一条安装命令，加迁移开关即可（安装器会转交 `migrate.mjs`，并在宿主未停时拒绝）：

```powershell
# Windows
.\install.ps1 -Migrate
```
```bash
# macOS / Linux
./install.sh --migrate
```

安装器会先提示影响（文件数/句数/预计耗时），**你确认后**才执行；执行完提示「重启 DSH 后生效」。

### 入口 B：会话内命令（需插件已加载）

在 DSH 会话里直接敲：

```
/memory-migrate            # 无参 = 只读检测（等价 --detect）
```

> 注意：**会话内 DSH 必然在运行**，而迁移必须在宿主停止时写库，所以 `--apply` 在会话内通常会被拒绝（退出码 2，并打印依据与两条出路）。
> 目前请按提示改用入口 A 或 C；后续版本会支持「登记迁移，下次启动自动执行」。

### 入口 C：手工 node 命令（最可控）

```bash
# 1) 只读检测
node <插件目录>/memtopic/src/migrate.mjs --detect

# 2) 完全退出 DSH（含托盘/后台进程）后执行迁移
node <插件目录>/memtopic/src/migrate.mjs --apply --yes

# 3) 如果检测到"库已有数据但你还想把旧 md 合并进来"
node <插件目录>/memtopic/src/migrate.mjs --apply --yes --merge
```

可选参数：

| 参数 | 用途 |
|---|---|
| `--yes` | 非交互确认（**安装器/Agent/脚本必须带**；缺省时非 TTY 会直接拒绝，退出码 1） |
| `--merge` | 库已有数据时，显式确认"把旧 md 合并进来"（不加则已迁移时只提示、不写库） |
| `--assume-host-stopped` | 你确认 DSH 已完全退出，但检测误报"运行中"时使用 |
| `--no-process-scan` | 受限环境（无法列进程）时只用锁/pid 文件判定；此时状态为"未知"，`--apply` 仍会拒绝，需配 `--assume-host-stopped` |
| `--db <file>` | 指定主题库路径（默认 `<记忆目录>/.memtopic/mem.db`） |
| `--md-root <dir>` | 指定记忆目录（默认 `~/.dsh/memory`） |
| `--dsh-home <dir>` | 宿主主目录（默认 `~/.dsh`；只读探测锁/pid/进程） |
| `--json` | 输出机器可读 JSON（安装器/Agent 用） |

### 迁移过程会做什么

`--apply` 会依次执行（每阶段先落快照 + checkpoint，失败可续跑）：

1. **检测**（只读）→ 2. **生成迁移计划**（只读）→ 3. **执行**：
   - `import`：旧 md 逐字导入主题库（同主题重复行只收一次；导出视图标记行自动跳过）；
   - `curate`：只读聚类，产出 `curation-proposals.json`（**只出建议，不自动合并**）；
   - `apply-merge`：按设计跳过（不做自动批量合并）。
4. **摘要**：主题数 / 句数 / 导入句数 / 耗时 + 「★ 下一步：重启 DSH 后生效」。

> **归类分组留待 DSH 内的 dream 整理，不影响检索**：句子已经全部入库，只是暂未分组，不丢任何内容，也不会影响 `memory_search`。

## 2. 迁移后：重启 DSH

迁移写的是 `~/.dsh/memory/.memtopic/mem.db`；**插件在启动时读取主题库**，所以：

1. 完全退出 DSH（含托盘/后台进程）；
2. 重新打开 DSH；
3. 设置页/状态卡应显示「主题库已启用：主题 N / 句 N」；`memory_search` 可用。

> 重启前旧插件仍按 md 模式工作，旧记忆不会消失，只是新写入还不会进主题库。

---

## 3. 回滚

迁移自带快照与 checkpoint，随时可回退：

```bash
# 回滚全部（apply-merge → curate → import 逆序；升级前无库则删库）
node <插件目录>/memtopic/src/migrate.mjs --rollback

# 只回滚某一阶段
node <插件目录>/memtopic/src/migrate.mjs --rollback=import
node <插件目录>/memtopic/src/migrate.mjs --rollback=curate        # 无库写入，实际为 no-op
node <插件目录>/memtopic/src/migrate.mjs --rollback=apply-merge   # 逐簇 undoMergeCluster
```

回滚说明：

- 迁移前**没有库** ⇒ 回滚 = 删除新建的库文件（旧 md 原样保留）；
- 迁移前**已有库** ⇒ 回滚 = 恢复迁移前自动快照（`<库目录>/upgrade/snapshots/pre-import-*.db`）；
- 回滚只影响主题库，**md 从头到尾没被改过**；
- 回滚后想再迁移，直接重新 `--apply --yes` 即可。

迁移前也可手动多备份一份：

```bash
node <插件目录>/memtopic/src/migrate.mjs --snapshot
```

## 4. FAQ

**Q1：迁移会把 md 文件删掉/改掉吗？**
不会。迁移对 md **只读**：不删除、不改写、不移动。迁移后 md 依然可以直接用编辑器打开阅读。
（插件跑起来后，`projects/`、`sessions/`、`knowledge/`、`tools/` 会作为**导出视图**由主题库重新生成；`global.md`、`index.md` 是人工稳定层，仍由你自己维护。旧的历史 md 留着不影响使用，确认不要了可自行归档。）

**Q2：迁移要多久？**
只与 md 文件数与句数有关，一次性开销：
- 小库（几十文件/几百句）：**秒级**；
- 大库（约 465 文件 / 3.1 万句）：**约 1–2 分钟**（首次新建库实测 111.5 秒；库已存在时二次执行只做幂等校验，通常 < 10 秒）。
迁移期间请勿关闭进程；万一中断，重跑 `--apply` 会从 checkpoint 续跑，不会重复导入。

**Q3：迁移中会写入多少数据？**
主题库会新增：主题（每人一个主题）+ 句子（逐字）+ 别名/触发词 + 审计记录；同时 `--apply` 会在 `<库目录>/upgrade/` 留 checkpoint、每阶段报告、迁移前快照（快照大小≈库文件大小）。旧 md 不变。

**Q4：迁移后旧的 md 还能读吗？**
能，而且插件仍会用它们（作为导出视图/人工稳定层）。迁移的意义是让**新写入**进主题库、检索走主题库；不是把 md 作废。

**Q5：检测说「DSH 正在运行」，但我明明已经关了？**
以进程扫描为准（任务管理器里搜 `DeepSeek Harness`，把残留进程结束）。确认已完全退出后，重新执行；仍误报可加 `--assume-host-stopped`。

**Q6：忘了加 `--yes`，报"非交互环境必须显式 --yes"？**
这是安全设计（退出码 1，未做任何写入）。在安装器/Agent/脚本里调用必须带 `--yes` 或先在交互终端确认。

**Q7：检测说「已迁移，无需操作」，但我又写了新的 md 文件？**
主题库已经是真源，新写入应走 `memory_note`（4.5.1 起主代理唯一写入口；`memory_write` 仅 dream 可用）；若确有历史 md 想补进来，用 `--apply --merge --yes`（幂等，已导入的句子不会重复）。

**Q8：迁移后需要做什么？**
**重启 DSH**。其余无需操作；归类分组会由 DSH 内的 dream 整理逐步完成，不影响检索。

**Q9：迁移安全吗？会不会把库搞坏？**
- 每阶段前自动快照 + checkpoint；失败回滚整阶段（不会写一半）；
- 导入走事务，`verify()` 校验库完整性；
- 重复执行幂等（第二次 +0 主题/+0 句）；
- 全程 md 只读；退出码 0/1/2/3/4 对应成功/参数/拒绝/阶段失败/回滚失败，失败时 stderr 必给「下一步」。

---

## 5. 退出码（给脚本/Agent）

| 退出码 | 含义 |
|---|---|
| `0` | 成功（或按设计跳过：已迁移/无可迁移数据） |
| `1` | 参数错误 / 非交互未确认（缺 `--yes`） |
| `2` | 拒绝执行（宿主运行中 / 状态未知 / 库版本过高） |
| `3` | 迁移阶段失败（可重跑续跑；先看 `<库目录>/upgrade/upgrade-report-*.json`） |
| `4` | 回滚失败（保留现场，从快照恢复） |

失败时 stderr 会有一行 `下一步：…`，照着做即可。

## 6. 从 4.0.1 升级到 4.5

> 适用：已经在 4.0.x（主题库已是真源）。
> **结论先说：不需要迁移数据**——主题库（`.memtopic/mem.db`）、`.config.json`、`AGENTS.md` 全部沿用；
> **重跑安装命令 + 重启 DSH** 即可。4.5 删除了漏网归档链与 `memory_archive_checkpoint` 工具，工具列表会变。

### 6.1 升级步骤

| 情况 | 做法 |
|---|---|
| 普通升级（推荐，绝大多数） | 重跑安装命令（与首次安装同一条）→ 完全退出并重启 DSH |
| Windows | `irm https://raw.githubusercontent.com/Starry0214/dsh-memory/main/install.ps1 \| iex` |
| macOS / Linux | `curl -fsSL https://raw.githubusercontent.com/Starry0214/dsh-memory/main/install.sh \| bash` |
| 想先看会改什么 | 加 `-CheckOnly`（sh：`--check`）：只校验、不写文件 |
| 离线 / 内网 | 下载 4.5.1 的 `install-manifest.json` + payload zip（以 manifest 的 `zip.name` 为准，本次为 `payload/dsh-memory-4.5.1.zip`）放同一目录，用 `-LocalPayload`（sh：`--local-payload`） |

安装器会：备份旧插件到 `_backup-<时间戳>/` → 写入新 `index.js` / `client/**` / `memtopic/src/*.mjs` → 逐文件校验 payload sha256（20 个文件）→ 重启后生效。

> 4.0.1 → 4.5 **没有数据库结构迁移步骤**：`mem.db` 原样读取，4.5 新增的笔记主题（`笔记·<wsKey>/<sid8>`）在第一次 `memory_note` 时按需自动创建。

### 6.2 AGENTS.md 怎么处理（唯一需要留意的文件）

安装器按**内容指纹**识别 `~/.dsh/AGENTS.md`（共享文件，全局一份），分两种情况：

| 你的 AGENTS.md | 安装器行为 |
|---|---|
| 仍是**旧模板**（原始 v4 `45463dd54b87c890bd7fd8e11a96a80ebeab96ffb597c77a93d8247d1d662e58` / 4.5.0 模板 `2de634f589f042f970826883368af374ff25f8159c94150996ff37222186b066`） | **先备份原文件，再自动替换为新版**：补上 `memory_note` 会话笔记纪律，并把写入通道改为「主代理只写 `memory_note`」 |
| 你**改过**（任何实质内容变化） | **保留你的文件 + 打印提示**，绝不覆盖；请对照新版手工补三条：① 会话笔记用 `memory_note`；② 不要再调用 `memory_archive_checkpoint`（工具已删除）；③ 写入通道（4.5.1）：主代理只写 `memory_note`，`memory_write` 仅 dream 可用 |

> 新版模板仍是 `<!-- dsh-memory-agents-template: v4 -->`——**v4 是协议代号，不随插件版本变**；安装器靠内容 sha256 区分「原始模板 / 用户改过」。

### 6.3 升级后行为变化

| 变化 | 你会感觉到 | 怎么办 |
|---|---|---|
| 漏网归档链整体删除（-2860 行） | `memory_archive_checkpoint`、`stale_archive` 工具消失 | 关键内容用 `memory_note`（主代理唯一写入口；`memory_write` 仅 dream 可用）；压缩检查点仍自动写 |
| **写入通道收紧（4.5.1）** | 主代理 / 普通子代理 / teammate 调 `memory_write` 返回 `ok:false, code=WRITE_DREAM_ONLY`；长期库（主题正文）只由 dream 维护 | 改用 `memory_note`（append-only，dream 整合时提炼进长期库）；这是有意的行为变更，不是故障 |
| 子代理摘要通道退役 | `/subagents-archive` 只回一条下线提示 | 用 `session_search` 检索子代理会话原文（覆盖 585/585） |
| 面板漏网控件删除 | 设置页不再有「漏网会话检测天数 / 处置方式」；原天数改名「子代理摘要回溯天数」 | 无需操作（该参数仍被子代理摘要通道读取） |
| 新增 `memory_note` | 工具列表多一个；笔记主题按需自动创建 | **无需迁移**，直接可用 |
| 压缩后改为「拦截式重灌」 | 压缩后的下一次请求前可能多等一会儿（上限 120 秒），但不再出现「模型先醒、记忆后到」的失忆窗口 | 正常现象；超时自动降级，不阻塞会话 |
| 检查点注入改为四段 | 压缩后注入更准：检查点 2400 + 笔记 1900 + 项目 1150 + 画像 350（body 5800，整块上限 6100 字），带优先级标注与截断恢复指针 | 无需操作 |
| 新增 15% 档位笔记提醒 | 上下文每跨 15% 提醒一次「有值得记的就 `memory_note`」 | 觉得烦可忽略（只提示，不阻塞） |

### 6.4 验证方法（怎么确认升级成功）

按顺序检查，全部命中即升级成功：

1. **启动日志**：出现 `[dsh-memory] 就绪 v4.5.1（构建 <8 位指纹>）`（指纹是插件自读本文件的 sha256 前 8 位，可当场核验「哪份字节生效」）。
2. **工具列表**：有 `memory_note`；`memory_write` 仍在列表但仅 dream 可用；**没有** `memory_archive_checkpoint` / `stale_archive`。
3. **设置页**（设置 → 通用设置 → 记忆）：有「子代理摘要回溯天数」，**没有**「漏网会话处置方式」控件。
4. **命令**：`/subagents-archive` 返回「子代理摘要通道已于 2026-11-05 退役」提示（不再执行归档）。
5. **安装器自检**：`install.ps1 -CheckOnly`（sh：`--check`）→ `[2/11] payload 完整性` 显示 `20/20 个文件 sha256 全部匹配`、patch 层 `dsh-memory` 与 `dsh-memory-client` 各一行、junction 指向插件目录。
6. **笔记通道 + 写入闸**：会话里让 AI `memory_note` 记一条 → `memory_search "笔记·"` 能命中本会话主题 `笔记·<wsKey>/<sid8>`；让主代理调 `memory_write` 应返回 `ok:false, code=WRITE_DREAM_ONLY`（4.5.1 起）；子代理调 `memory_note` 应返回 `SUBAGENT_SKIP`。
7. **重灌链路**（可选，需触发一次压缩）：日志出现 `压缩后重灌·等待检查点 <N>ms` 与 `压缩后记忆重灌已构建：<N> 字`；超时会打印降级但仍注入。
8. **知识图谱**（可选）：打开 `/dsh-memory/stats` → 图谱节点按 `kind` 三色区分（笔记 / 检查点 / 普通主题）。

> 若第 1、2 条不成立，99% 是**没重启 DSH**（插件代码不热更新）或装到了非实际启动的 profile——先看 `-CheckOnly` 的「目标 profile」一行。

### 6.5 回退

- 安装器每轮都在 `_backup-<时间戳>/` 留旧插件：把旧 `index.js` / `client/**` / `memtopic/src/*.mjs` 放回后重启即可；本地留有 4.0.1 的 payload zip 时，也可 `-LocalPayload` 重跑旧版。
- 主题库**不会被降级或删除**：4.5 期间新增的 `笔记·` 主题在 4.0.1 里只是普通主题（**不丢内容**，只是不会被自动提炼）。
- `.config.json` 无需改动；`staleAction` 字段保留在配置 schema 里（仅为兼容旧配置，4.5 面板已无控件）。
