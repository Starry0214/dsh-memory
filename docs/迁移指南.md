# 记忆库迁移指南（老用户：md → 主题库）

> 适用范围：**老用户**（`~/.dsh/memory/` 下已有旧版 md 记忆，主题库为空或不存在）。
> 迁移只做一件事：把旧 md 的正文导入 SQLite 主题库（`.memtopic/mem.db`），让插件的新记忆协议（`memory_search`/`memory_write`/`memory_dream_patch`/`memory_archive_checkpoint`）可用。
> **md 不会被删除、不会被改写**；迁移可回滚、可重复执行。

---

## 0. 先检测（只读，不改任何东西）

三种入口任选其一（见第 1 节），推荐先跑一次检测：

```bash
node <插件目录>/memtopic/src/migrate.mjs --detect
```

输出会明确告诉你三件事：

1. **旧版 md 有多少**：sessions / knowledge / projects / tools 各多少文件、多少句；
   `global.md` / `index.md` 属"人工稳定层"，**不导入**（可直接用编辑器改）。
2. **主题库状态**：是否存在、已有多少主题/句子、`schema_version`。
3. **建议动作**：
   - `⚠ 检测到旧版 md 记忆，需要迁移` → 看第 1 节执行迁移；
   - `✓ 已迁移（主题库已有数据，无需操作）` → 什么都不用做，旧 md 保留是正常的；
   - `○ 空库（没有可迁移的 md）` → 直接用插件即可。

检测还会报告 **DSH 是否正在运行**（依据：进程扫描 / 锁与 pid 文件，逐条列出）。迁移要求 DSH 已完全退出。

---

## 1. 三种迁移入口

### 入口 A：重跑安装器（推荐）

老用户重跑同一条安装命令，加迁移开关即可（安装器会转交 `migrate.mjs`，并在宿主未停时拒绝）：

```powershell
# Windows
.\install.ps1 -Migrate
```
```bash
# macOS / Linux
./install.sh --migrate
```

安装器会先提示影响（文件数/句数/预计耗时），**你确认后**才执行；执行完提示「重启 DSH 后生效」。

### 入口 B：会话内命令（需插件已加载）

在 DSH 会话里直接敲：

```
/memory-migrate            # 无参 = 只读检测（等价 --detect）
```

> 注意：**会话内 DSH 必然在运行**，而迁移必须在宿主停止时写库，所以 `--apply` 在会话内通常会被拒绝（退出码 2，并打印依据与两条出路）。
> 目前请按提示改用入口 A 或 C；后续版本会支持「登记迁移，下次启动自动执行」。

### 入口 C：手工 node 命令（最可控）

```bash
# 1) 只读检测
node <插件目录>/memtopic/src/migrate.mjs --detect

# 2) 完全退出 DSH（含托盘/后台进程）后执行迁移
node <插件目录>/memtopic/src/migrate.mjs --apply --yes

# 3) 如果检测到"库已有数据但你还想把旧 md 合并进来"
node <插件目录>/memtopic/src/migrate.mjs --apply --yes --merge
```

可选参数：

| 参数 | 用途 |
|---|---|
| `--yes` | 非交互确认（**安装器/Agent/脚本必须带**；缺省时非 TTY 会直接拒绝，退出码 1） |
| `--merge` | 库已有数据时，显式确认"把旧 md 合并进来"（不加则已迁移时只提示、不写库） |
| `--assume-host-stopped` | 你确认 DSH 已完全退出，但检测误报"运行中"时使用 |
| `--no-process-scan` | 受限环境（无法列进程）时只用锁/pid 文件判定；此时状态为"未知"，`--apply` 仍会拒绝，需配 `--assume-host-stopped` |
| `--db <file>` | 指定主题库路径（默认 `<记忆目录>/.memtopic/mem.db`） |
| `--md-root <dir>` | 指定记忆目录（默认 `~/.dsh/memory`） |
| `--dsh-home <dir>` | 宿主主目录（默认 `~/.dsh`；只读探测锁/pid/进程） |
| `--json` | 输出机器可读 JSON（安装器/Agent 用） |

### 迁移过程会做什么

`--apply` 会依次执行（每阶段先落快照 + checkpoint，失败可续跑）：

1. **检测**（只读）→ 2. **生成迁移计划**（只读）→ 3. **执行**：
   - `import`：旧 md 逐字导入主题库（同主题重复行只收一次；导出视图标记行自动跳过）；
   - `curate`：只读聚类，产出 `curation-proposals.json`（**只出建议，不自动合并**）；
   - `apply-merge`：按设计跳过（不做自动批量合并）。
4. **摘要**：主题数 / 句数 / 导入句数 / 耗时 + 「★ 下一步：重启 DSH 后生效」。

> **归类分组留待 DSH 内的 dream 整理，不影响检索**：句子已经全部入库，只是暂未分组，不丢任何内容，也不会影响 `memory_search`。

## 2. 迁移后：重启 DSH

迁移写的是 `~/.dsh/memory/.memtopic/mem.db`；**插件在启动时读取主题库**，所以：

1. 完全退出 DSH（含托盘/后台进程）；
2. 重新打开 DSH；
3. 设置页/状态卡应显示「主题库已启用：主题 N / 句 N」；`memory_search` 可用。

> 重启前旧插件仍按 md 模式工作，旧记忆不会消失，只是新写入还不会进主题库。

---

## 3. 回滚

迁移自带快照与 checkpoint，随时可回退：

```bash
# 回滚全部（apply-merge → curate → import 逆序；升级前无库则删库）
node <插件目录>/memtopic/src/migrate.mjs --rollback

# 只回滚某一阶段
node <插件目录>/memtopic/src/migrate.mjs --rollback=import
node <插件目录>/memtopic/src/migrate.mjs --rollback=curate        # 无库写入，实际为 no-op
node <插件目录>/memtopic/src/migrate.mjs --rollback=apply-merge   # 逐簇 undoMergeCluster
```

回滚说明：

- 迁移前**没有库** ⇒ 回滚 = 删除新建的库文件（旧 md 原样保留）；
- 迁移前**已有库** ⇒ 回滚 = 恢复迁移前自动快照（`<库目录>/upgrade/snapshots/pre-import-*.db`）；
- 回滚只影响主题库，**md 从头到尾没被改过**；
- 回滚后想再迁移，直接重新 `--apply --yes` 即可。

迁移前也可手动多备份一份：

```bash
node <插件目录>/memtopic/src/migrate.mjs --snapshot
```

## 4. FAQ

**Q1：迁移会把 md 文件删掉/改掉吗？**
不会。迁移对 md **只读**：不删除、不改写、不移动。迁移后 md 依然可以直接用编辑器打开阅读。
（插件跑起来后，`projects/`、`sessions/`、`knowledge/`、`tools/` 会作为**导出视图**由主题库重新生成；`global.md`、`index.md` 是人工稳定层，仍由你自己维护。旧的历史 md 留着不影响使用，确认不要了可自行归档。）

**Q2：迁移要多久？**
只与 md 文件数与句数有关，一次性开销：
- 小库（几十文件/几百句）：**秒级**；
- 大库（约 465 文件 / 3.1 万句）：**约 1–2 分钟**（首次新建库实测 111.5 秒；库已存在时二次执行只做幂等校验，通常 < 10 秒）。
迁移期间请勿关闭进程；万一中断，重跑 `--apply` 会从 checkpoint 续跑，不会重复导入。

**Q3：迁移中会写入多少数据？**
主题库会新增：主题（每人一个主题）+ 句子（逐字）+ 别名/触发词 + 审计记录；同时 `--apply` 会在 `<库目录>/upgrade/` 留 checkpoint、每阶段报告、迁移前快照（快照大小≈库文件大小）。旧 md 不变。

**Q4：迁移后旧的 md 还能读吗？**
能，而且插件仍会用它们（作为导出视图/人工稳定层）。迁移的意义是让**新写入**进主题库、检索走主题库；不是把 md 作废。

**Q5：检测说「DSH 正在运行」，但我明明已经关了？**
以进程扫描为准（任务管理器里搜 `DeepSeek Harness`，把残留进程结束）。确认已完全退出后，重新执行；仍误报可加 `--assume-host-stopped`。

**Q6：忘了加 `--yes`，报"非交互环境必须显式 --yes"？**
这是安全设计（退出码 1，未做任何写入）。在安装器/Agent/脚本里调用必须带 `--yes` 或先在交互终端确认。

**Q7：检测说「已迁移，无需操作」，但我又写了新的 md 文件？**
主题库已经是真源，新写入应走插件工具（`memory_write` 等）；若确有历史 md 想补进来，用 `--apply --merge --yes`（幂等，已导入的句子不会重复）。

**Q8：迁移后需要做什么？**
**重启 DSH**。其余无需操作；归类分组会由 DSH 内的 dream 整理逐步完成，不影响检索。

**Q9：迁移安全吗？会不会把库搞坏？**
- 每阶段前自动快照 + checkpoint；失败回滚整阶段（不会写一半）；
- 导入走事务，`verify()` 校验库完整性；
- 重复执行幂等（第二次 +0 主题/+0 句）；
- 全程 md 只读；退出码 0/1/2/3/4 对应成功/参数/拒绝/阶段失败/回滚失败，失败时 stderr 必给「下一步」。

---

## 5. 退出码（给脚本/Agent）

| 退出码 | 含义 |
|---|---|
| `0` | 成功（或按设计跳过：已迁移/无可迁移数据） |
| `1` | 参数错误 / 非交互未确认（缺 `--yes`） |
| `2` | 拒绝执行（宿主运行中 / 状态未知 / 库版本过高） |
| `3` | 迁移阶段失败（可重跑续跑；先看 `<库目录>/upgrade/upgrade-report-*.json`） |
| `4` | 回滚失败（保留现场，从快照恢复） |

失败时 stderr 会有一行 `下一步：…`，照着做即可。
