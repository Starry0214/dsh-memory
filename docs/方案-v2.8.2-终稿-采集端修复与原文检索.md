### §2.2 BUG-2 修法（三保险，~4 行）

根因席指出 `kind` 方案的两处漏洞：**"建议"必须改"必填"**；`p.kind !== "marker"` 是 **fail-open**（新件型忘标记就自动算内容）。⇒ 改为：

1. **标记另存 `markers` 数组，不入 `parts`**（`joinParts` 天生只吃对象 —— 最彻底）
2. **另设 `realPieces` 计数**用于 `L3241` 守卫
3. `joinParts` 加**运行时断言** `p && typeof p.s === "string"`（类型混装今后**当场抛错**，不再静默变空）

**不变量（根因席，须写进门而非只写注释）**：
> **"内容性必须被显式标记并贯穿全链；任何用 `length`／字段真值性判定'有没有内容'的站点，一律视为缺陷。"**

**`kind` 必须贯穿**（否则每级重新发明长度判据）：`compressUnit`（`L3283` 的 `segments.length>0`）／`bucketUnits`（`L3316` 的 `u.chars || u.text.length`，**信任声明字段**——error/none 路径（`L3278/3307`）返回 `chars:0` 而 text 非空 ⇒ 预算**低估**、桶可超 `BUCKET_BUDGET_CHARS`）／`readUnitCache`（`L3339` 仅校验 `typeof text === "string"`）／`mergeUnitCache`（`L3366` 仅 `slice`）。
**过滤必须白名单** `CONTENT_KINDS.has(p.kind)`，**不得** fail-open。
**真正钉住修法的门**：**任一进入单元缓存的 unit，去掉标记行后必须非空白**（AC-P0-1/2 只查两个样本，查不出这**一类**）。

**同型清单（现存，根因席列出，P0 一并记入风险而非全修）**：`L3241` → `L3283` → `L5794/5803/5809`（**同一判据抄三遍**）→ `L5811 if (unit && unit.text)`（真值性）——**三道串联守卫全放行**，这才是 17 换行进缓存的原因；另 `L3155 frames.length===0`（magic 条数当"有内容"）、`L4383 applied.length>0`（"写了一条 patch"当"本轮有产出"）。
**正确形态样板**：`L3201/L3208 if (!txt) continue` —— 判**字符串本身**。

### §2.3 BUG-1 修法：**单遍全帧 + 尾部环形缓冲**（六席中工程席与根因席**独立同结论**）

**先纠 v2.8.1 的错**：我写的"两遍扫描，第二遍只解少量帧"**成本模型错** —— pass 1 的快筛作用在**解压后的文本**上 ⇒ **必须解压全部帧**，总计 ≈1.0–1.1×，不是"多一遍 4.6 s"。且两遍会把同一 KEEP 谓词**抄两处**（`L3191-3194` vs pass-1），正是"两口径漂移"的经典缝。

**采用写法**：

1. **删掉 `K`/`selected`/FULL 三分支的采样逻辑**，**单遍遍历全部帧**（`FULL` 只保留给 **≤12 帧**的微型会话做 sanity —— 消除 v2.8.1 "一句取消 FULL、一句保留 FULL" 的自相矛盾）
2. 提取到 piece 即 push，同时维护**尾部环形缓冲**（容量 40K 字符，滚存最近 piece）
3. `total > maxChars` **不 break**，只置 `truncated = true` 并停止**头段**累加
4. 组装 = `头段.slice(0, maxChars - TAIL_CAP)` + 尾部缓冲 + 既有 `note()`
5. **每 64 帧让出一次**（现 `L3182` 每帧 `await setImmediate`；全帧化后 8.6 万帧 = 8.6 万次事件循环往返，估 0.4–2 s）

⇒ 与"按内容选帧"**等价**（都是按内容、首尾保真），但**只解一遍**。

**⚠ 必须补的规格（根因席）**：现行代码在"超预算谁胜出"上**已自相矛盾**——messageflow 分支 `L3223 break` **保头**，compaction 分支 `L3238 slice(-maxChars)` **保尾**。§2.4（原）只补注释不改行为 ⇒ 采样修好后**"最近说的话"仍可能被保头规则挤掉**，而这是原文检索最常见的用法。⇒ **必须写死预算分配规则**：**压缩摘要 > 用户消息 > 助手消息 > 工具**；同级**新近优先**；messageflow 分支改**保尾**。

**成本实测**：0.172 s/MB（逐帧即弃）⇒ 全帧化在后台归档轮次可接受；**内存**：逐帧即弃 maxRSS **211.5 MB**（同一 27.27 MB 日志），**concat 路径 922.9 MB** ⇒ **禁止 concat**。

## §3 P1：原文检索 CLI

### §3.1 布局（段列表**只许来自 manifest**）

```
~/.dsh/tools/session-search/{session-search.mjs, README.md}
~/.dsh/session-text/<sid归属日>/<完整uuid>/{manifest.json, seg-000N.jsonl}
```

- **★ 段列表只来自 `manifest.json`**（提案人席）：若检索侧用 glob `*.jsonl`，**重建后的孤儿段会被 rg 搜到 → 返回过期正文**（"看起来能搜、搜的是旧内容"）
- **★ 归属日算法写死** = 该 sid **全部日志文件的 `max(mtime)` 所在日**（整个 sid 落**一个**目录；7 个劈开 sid 不会拆）
- **★ 段数有界**（红队）：每次增量新开段会让长活会话无限增长 ⇒ **每 sid 段数上限 + 滚动合并**（上限值待定，建议 16）
- 缓存**不放** `~/.dsh/memory/`（否则被 `scanUndeposited L1545`／检索候选集／面板统计／预算告警扫到）

### §3.2 收录口径（单一来源 `KEEP_KINDS`）

**★ 定义**一个** `KEEP_KINDS` 常量同时驱动** cache 收集与 extractor 判定（根因席指出**现存不一致**：cache KEEP 含 `system/message`，而 extractor 四类 `L3191-3194` **不含** ⇒ 两个产物对"内容"定义不同）。

| 类型 | 收 | 抽取路径 |
|---|---|---|
| `user/message` | ✅ | `data.content[]` 中 `type==="text"` 的 `c.text` |
| `assistant/message` | ✅ | `data.message.content[]` 中 **`filter(c => c.type === "text")`** |
| `system/message` | ✅ | 同 assistant 路径 |
| `tool/call` | ✅ | `data.name` + `data.arguments` |
| `tool/result` | **仅错误** | 判据见下 |
| `compaction/summary` | ✅ | `data.summary[]` 中 `type==="text"` |
| chunk 四类 / `request/header` / 其余控制事件 | ❌ | — |

**四处写死（实测裁决）**：
1. **错误判据 = `content[].isError === true`**（A = `data.error != null`，B = `content[].isError`；**B 是超集**：跨 18 个日志查出 3 例 `isError:true` 而 `data.error === undefined`，正文均为 `Error: sandbox escalation…`）。**绝不可只用 A，绝不可字符串嗅探**
2. **`assistant/message` 必须 `filter(type==="text")`** —— `reasoning` 块**也带 `text` 字段**，naive `map` 会**吞进 reasoning 全文**；且实测 **48 条中 12 条（25%）无 text 块** ⇒ 需**单独计数"类内空正文"**
3. **两条路径不同**：`user/message` → `data.content[]`；`assistant/message` → `data.message.content[]`
4. **`compaction/summary` 无实测覆盖**（两席样本均 0 条）⇒ **门必须专门造夹具**

**丢弃必须分类计数**，且**必须写明落点**（提案人席）：`manifest.json` 的 `dropped: {kind: n}` **逐轮累加**（"长期指标"必须有落点，不能只打印）。
**长期指标的含义**：宿主改事件名那天，覆盖面会**静默变化** ⇒ 丢弃计数是唯一能发现它的东西。

### §3.3 缓存行格式

```json
{"k":"_meta","ver":1,"sid":"<完整uuid>","files":[…],"built":"…","dropped":{"…":0}}
{"t":1789006838082,"k":"user/message","s":9,"f":"session.jsonl.zstd","x":"…逐字…"}
```
- **一行一事件**；换行**交给 `JSON.stringify` 单次编码**，**禁手工二次转义**（唯一逆变换）
- `x` **逐字**，不截断/不改写/不脱敏；`f` 标注物理文件；`s` = **源帧序号**（**不是**缓存行号）

### §3.4 身份键与归并

- 一个 sid 收目录下**全部** `.zstd`（**不是**两个已知名字 —— 否则 DSH 再改名成 v4 会**静默漏收第三个文件**）
- **身份校验**：解码帧 0，其 `session` 头 `session.id` 必须等于目录 sid
- **★ 校验不符时：中止该 sid 的构建并记录到 `.build-errors.log`，不静默跳过**（提案人席问"继续还是中止"⇒ 定：**中止该 sid、继续其他 sid、并在报告里单列**）
- **★ 文件序写死 = `mtime` 升序**（7/7 劈开案例只靠 mtime 不重叠才成立）
- **主排序键 = `(文件序, 帧序, 帧内行序)`**；`time` 仅展示 + overlap 校验
- 两文件 `time` 区间重叠 → **报 `overlap` 并中止该 sid**（不静默按文件序拼）

### §3.5 水位与增量（工程席给出 API 层硬约束）

**★ Node 的 zstd API 不返回"本帧消费了多少字节"**（`decompressFrameAt` 只返回 Buffer）⇒ **拿不到帧结束偏移**。

```jsonc
{ "name":"session.v3.jsonl.zstd", "size":1234567, "frames":4734,
  "lastFrameOff":1046520,            // 最后一个已消费帧的**起始**偏移
  "lastFrameDigest":"sha256:<前16>", // 该帧解压内容
  "badOffsets":[…] }
```
续跑：`offs = scanZstdFrames(buf)` → **先验** `digest(decompressFrameAt(buf,lastFrameOff)) === lastFrameDigest`（不符 → 全量重建）→ `i = offs.findIndex(o => o > lastFrameOff)` → `i<0` 无新增；否则从 `i` 起逐帧 → 只写新 `seg` → 原子替换 manifest。
**★ 若写成 `lastFrameOff + 4`，续跑会重新命中同一帧 → 重复行。**

**三条必须同时满足的约束（根因席）**：
1. 水位是**"最后一个已消费帧的起始偏移"**，不是"已消费字节数"（后者在半帧处**二义**）
2. **失败/残帧不得推进偏移**（否则半帧被永久跳过）
3. **偏移检不出"同尺寸原地重写"** ⇒ 单帧摘要只能证明"该帧没变"，**检不出全文件被换** ⇒ 需**另配 `size` + `mtime`**，或**明写检测边界**并接受"重写即全量重建"的成本
4. **伪 magic**：`scanZstdFrames` 逐字节扫，压缩体内可能出现伪 magic → `decompressFrameAt` 返回 null。若实现把它当"停下、下轮再来"，水位**永不前进（死循环式停滞）** ⇒ **必须 `continue` 并把该偏移记入 `badOffsets` 让水位越过**（`L3185` 的 `if (!_fb) continue;` 是同款正确先例）

### §3.6 原子性与并发

- 段文件**写一次永不修改**；`manifest.json` **唯一可变点**，`tmp → rename`
- **不用"增量 = 重写整档"**（那是"只省 CPU 不省 I/O"：最大 sid 60.1 M 字符 ≈ 80 MB）
- **并发**：两进程同构建同 sid → 无重复行、manifest 完整；查询与构建并发 → 读者只见完整文件
- **Windows**：`rename` 撞上正在读该文件的 `rg` 可能 `EPERM/EBUSY` ⇒ **重试退避**，测试必须覆盖

### §3.7 检索与输出（两个 P0 级不变量）

**不变量 A（坐标源侧化）**：输出每处坐标带标签 `cache:#1204` / `src:<file>#f12@0x1A3C`；`--show` **接受源坐标**并还原；缓存行号**只许用于同一次调用内的二次访问**。
- **★ 补齐（提案人席）**：`--show` 扫**哪些段**（答：**全部段，但只按 `f`+`s` 匹配，扫到即停**）；**★ 坐标已不存在（重建后）时：显式报"该坐标已失效（缓存已重建），请改用关键词重搜"，绝不返回邻近或空白结果**；**`s`（帧号）是准的**，字节偏移仅作辅助。

**不变量 B（截断不冒充命中数）**：先 `rg --count` 拿总数，**永远打印"命中 N 处（其中列出 M 条）"**，JSON 里 `total ≠ listed`；**绝不把截断后的条数当命中数**。

**零结果引导**（照抄 mimocode 语义）：显式声明「**0 结果 ≠ 没记录**」+ ①换更稀有的词②放宽 `--since`/去掉 `--kind`③**缓存可能滞后**。
**依赖缺失**：`rg` **实测不在 PATH**（二进制在 `@deepseek-ai/dsh/node_modules/@vscode/ripgrep-win32-x64/bin/rg.exe`）⇒ 工具**自行定位**；缺失时**显式报错 + 非零退出，绝不报 0 命中**。

### §3.8 `--replay`（第二个入口）

- **★ 时区与取值来源写死**（提案人席）：`--since/--until` 按**事件 `time` 的本地时区**，`--until` **含当天**（`<= 当日 23:59:59.999`）；并**允许 `--by-dir` 改为按目录归属日**
- 只列 `user/message`（全库 ~2.7%、约 5000 万字符），按时间铺出
- 适用"依稀记得但想不起词"：人记得的是**场景**不是词

### §3.9 内存纪律

逐帧即弃（禁 concat）／直写磁盘／**检索在进程外**（脚本永不把语料读进内存：124–149 M 字符 → UTF-16 **248–298 MB 堆常驻**）／一次一个 sid。
