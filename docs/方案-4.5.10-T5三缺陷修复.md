### 0.3 结论

三个独立缺陷叠加：

- **T5-1 归档不过滤**：`p3SessionEndSweep` 只判 `isSubagent / hasCheckpoint / idle`，不看归档 ⇒ 已归档会话每小时被扫、被 spawn（归档会话不能当父，只能回落到别的会话 ⇒ 子代理挂错工作区）。
- **T5-2 cid 同 tick 冲突**：同一 tick 内所有会话 cid 相同 ⇒ 幂等 meta 只让第一个写成功，其余全部 `dup-skip`（静默丢检查点）；`INTENT_PENDING` 队列键同样冲突。
- **T5-3 记账冒充成功**：`dup-skip` 被记成 `ok:1 / intent-ok-db`，账本上看不出「检查点没写进去」。

## 1. 目标 / 非目标

### 目标

1. 已归档会话不再被 T5 扫描/补写（不 spawn、不烧 token、不产生挂错父会话的子代理）。
2. 同一 tick 内多个会话的 cid 唯一 ⇒ 各自落库，不再互相 `dup-skip`。
3. 记账诚实：`dup-skip` 在账本里可区分，不再冒充「写成功」。

### 非目标（本版不做，避免扩大面）

- 不改 T1/T4 触发路径（其 cid 来自宿主 `compactionId`，天然唯一）。
- 不改 `agentsBySession` 生命周期（无 delete 是存量问题，涉及宿主 agent 销毁事件与 `LAST_TOP_AGENT` 交互，单独立项）。
- 不改 T6（`decideMissed` 全仓未被接线，引用数 0，只存在于 p3-triggers 与其单测）。
- 不改已发布的 4.5.10 label 改动（本方案复用其 `sid8Of()`）。

## 2. 拟改动（逐条，最小 diff）

### 改动 A：`decideSessionEnd` 增加 `isArchived`（纯函数）

`p3-triggers.js:183`：

```js
export function decideSessionEnd({ lastActivityAt, now, idleMs, isSubagent, hasCheckpoint, isArchived } = {}) {
  if (isSubagent === true) return { fire: false, reason: "subagent" };
  if (isArchived === true) return { fire: false, reason: "archived" };   // 新增
  ...
}
```

- 判定顺序：`subagent → archived → has-checkpoint → no-activity → invalid-now → not-idle → idle`。
- docstring 的 reason 列表同步加 `"archived"`（`p3-triggers.js:54`）。
- 保持纯函数（零 I/O、零时钟），单测可覆盖。

### 改动 B：sweep 传归档判定

`index.js:21246` 的 `decideSessionEnd({...})` 增加：

```js
isArchived: isArchivedAgent(ag),
```

- 复用既有 `isArchivedAgent`（内部 `readArchivedSessionIds()` 有 30s 缓存；每小时一次 sweep，缓存影响可忽略）。
- 不新造第二套归档读取逻辑。

### 改动 C：cid 用 `sid8Of(sid)` 唯一化

`index.js:21256`：

```js
const cid = "p3e-" + sid8Of(sid) + "-" + now.toString(36);   // 原：sid.slice(0, 8)
```

- 效果：`p3e-bca1141e-<b36>`（每会话每 tick 唯一）。
- 连带效果（预期）：meta 幂等键唯一、`INTENT_PENDING` 键唯一、检查点 header 可读性提升（`压缩 p3e-bca1`）。
- 历史兼容：旧 marker（`<!-- intent: p3e-session--… -->`）不会被新 cid 命中 ⇒ 不会误判 dup；`stripOldIntentBlocks` 按 `sid:` 后缀管理旧块，不受影响。

### 改动 D：dup-skip 记账区分

`index.js:15163-15172`（db 分支）：

- `route.duplicate === true` 时：
  - `p3CostBump("checkpointWrite", …, { sid, trigger: "I-dup", ok: 1, note: "intent-dup-skip" })`（与 `I-ok` 区分；`ok` 语义见「待裁决 D-1」）。
  - 返回对象保持 `{ ok: true, mode: "db", duplicate: true, topicName }`（调用方据此区分）。
- T5 `.then`（`index.js:21261-21273`）：记账 note 改为 `res && res.duplicate ? "session-end-dup" : "session-end"`；`checkpointAt` 仍只在 `ok` 时置。

### 改动 E（可选，建议采纳）：单轮 spawn 上限

`p3SessionEndSweep` 循环内加 `fired < T5_MAX_PER_SWEEP (3)` 上限；达到后 `break`，其余会话下个 tick 再补。

- 理由：cid 唯一化后，首个 tick 可能同时补写多个历史空闲会话（一次 burst 多个子代理 = token 风暴）。
- 依据：T6 `decideMissed` 历史口径 `DEFAULT_MAX_COUNT=3`。

### 改动 F（可选，建议采纳）：最大空闲窗口

`decideSessionEnd` 增加可选 `maxIdleMs`（默认 `DEFAULT_MAX_AGE_DAYS*86400000`，7 天）；`now - lastActivityAt > maxIdleMs` ⇒ `{fire:false, reason:"too-old"}`。

- 理由：T5 语义是「会话收尾」，空闲 3 天以上的会话补写价值极低；避免远古会话烧 token。
- 与改动 A 叠加：归档是硬过滤，窗口是软过滤。

## 3. 护栏清单（实现必须逐条落实，自证逐条对应）

1. 归档判定复用 `isArchivedAgent`（不新造第二套读取）；`reason:"archived"` 可观测（sweep 里 `monitorEvent("p3","t5-skip archived "+sid8)`，低频、每小时最多几条）。
2. cid 唯一性：同 tick 不同 sid 的 cid 必不同（单测断言 + 代码断言 `sid8Of` 输出不含 `"session-"`）。
3. `dup-skip` 不得记成 `intent-ok-db`（账本可区分）；T5 外层 note 同理。
4. T1/T4 路径 cid 不动（仍用宿主 `compactionId`）——回归断言。
5. 失败可重试：`st.endFired` 复位逻辑保持（spawn 失败/无输出 ⇒ 下个 tick 重试）；`queued` 语义见「待裁决 D-4」。
6. 单轮 spawn 上限（若采纳改动 E）：上限常量可测（`__p3Hooks` 或导出）。
7. 日志带值：cid / sid8 / reason / duplicate 全部落 `monitorEvent` 或 cost `ev`（不吞异常）。

## 8. 待审计裁决点

- **D-1**：`dup-skip` 的 `ok` 口径——记 `ok:1 + note:intent-dup-skip`（幂等命中算成功），还是 `ok:0`（不算成功，进失败率）？倾向前者（避免污染失败率），但要求 note 可区分。
- **D-2**：是否采纳改动 E（单轮 spawn 上限 3）。
- **D-3**：是否采纳改动 F（7 天最大空闲窗口）。
- **D-4**：`spawnIntentCheckpoint` 返回 `{ok:false, queued:true}`（忙入队）时，sweep 的 `endFired` 是否保持 true（视为已交办）？现状是复位 ⇒ 下 tick 重复排队。倾向：`queued` 视为已交办（保持 endFired=true），失败由队列自身重试机制兜底。
- **D-5**：`readArchivedSessionIds` 是否在 sweep 里 `{force:true}` 刷新（避免 30s 缓存窗口内刚归档的会话仍触发一次）？倾向不强制（每小时一次、30s 窗口可忽略），审计可推翻。
- **D-6**：改动 F 的窗口值取 7 天（与 T6 一致）还是更短（如 24h）？

### 9.2 必须修改项 M1–M8（已并入实现规格）

- **M1**：归档判定用 **sweep 循环内 `sid`**：`readArchivedSessionIds().has(sessionIdKey(sid))`（不用 `isArchivedAgent(ag)`——它依赖 `header.id`，与 `agentsBySession` 键是否恒等无法静态证明）；且**在 `p3SessionState(sid)` 之前**判定（R10：归档会话不再建/刷状态条目）。
- **M2**：`readArchivedSessionIds` 解析失败**不得用空集覆盖缓存**：保留上一份 + `monitorEvent("p3","archived-read-fail …")`；仅首轮无缓存才空集（fail-open 可见）。
- **M3**：cid 抽纯函数 `p3SessionEndCid(sid, now)`；新建 `__p3Hooks` 暴露 `sessionEndCid / maxPerSweep / healMs / shouldHealEndFired`。
- **M4**：记账三态——dup ⇒ `trigger:"I-dup", ok:1, n:0, note:"intent-dup-skip"`；queued ⇒ `note:"session-end-queued"` 且 `fail:0`；T5 外层 `n=(ok&&!dup)?1:0`。
- **M5**：`endFiredAt` + 自愈 `endFired && !checkpointAt && (now-endFiredAt>2h 或旧格式无 endFiredAt) ⇒ endFired=false`（+汇总 monitor）。
- **M6**：改动 E **必做**（cap=3）；`INTENT_PENDING` 去重/淘汰留痕（`pending-dedupe` / `pending-evict`），淘汰时复位被淘汰会话的 `endFired`。
- **M7**：归档/过期跳过日志**每 tick 汇总一条**（`t5-skip archived=<k> too-old=<m> healed=<h>`），不按会话逐条。
- **M8**：交付物补 **G-9 判据**（落库首行 `p3e-sess`→`p3e-<sid8前4>`，长度/结构不变；旧 meta 键停在 30 条）+ **实现前重跑 `node _run-suite.mjs` 取当次基线**（存 `_verify/suite-baseline-pre-t5fix-20261109.txt`）。

### 9.3 采纳的裁决（D-1~D-6 修订后）

- **D-1**：dup 记 `I-dup / ok:1 / n:0 / note:intent-dup-skip`（meta 只在写成功后写 ⇒ dup 必为真幂等命中，不算失败也不算一次写）。
- **D-2**：E 必做，cap=3（`INTENT_PENDING` 容量 5 且静默逐旧）。
- **D-3 / D-6**：F 采纳，窗口 **7 天**（`DEFAULT_MAX_AGE_DAYS*86400000`；不取 24h——会把 1–3 天合法收尾会话排除）。
- **D-4**：queued ⇒ `endFired` 保持 true（视为已交办）；失败仍复位；连续失败交给重试队列 + M5 自愈。
- **D-5**：sweep 开头 `readArchivedSessionIds({force:true})` **一次**（不是每会话 force）。

### 9.4 遗留（本批不做，审计 M9–M11，写进遗留清单）

- **M9**：T4 在压缩事件里无条件预置 `checkpointAt`（`index.js:18155-18157`）⇒ 压缩过但写失败的会话，T5 兜底永久失效。
- **M10**：T1 的 cid 同根缺陷（`index.js:21207/21210`，实测 `intent:p3t1-session--*`、首行 `p3t1-ses`）⇒ 建议用同一 `sid8Of` 单列修复。
- **M11**：`fireIntentRetry` 传触发者 agent 作 `parentAgent`（`index.js:13217`）⇒ T5 失败重试可能写进错误工作区线，并被 `p25ReadPreviousSession` 跨工作区桥接注入。
