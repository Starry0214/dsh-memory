> 基线：工作区源码 `dsh-memory-plugin\index.js`，sha16 `E2A54343775A91B9`，669,298 B，CHANGELOG 最新 v2.6.6

## §1 根因（三条，R1 只抓到半条）

**A. 同一预算多真源 + 量纲混用**（R1 抓到的）
- `CHAR_LIMIT`（字符，L1479）／`SIZE_WARN`（字节，L1480）／面板图例字面量（**L3852**）／`/dream` 健康自带第二真源（**L8568** `df === "global.md" ? 3000 : 2000`）／维护触发口径（L3385 `maintTriggerChars`、L5160 `MAINT_LIMIT_ALLOW=1500`）。
- 比较符也不一致：L1090 `<=` 才不截断 ｜ L6050 `chars > charLimit` ｜ **L8569 `>=`**（把 `chars == lim` 这一**合规态**误判为未达标）。
- 后果：改 `CHAR_LIMIT` 时 L8568 静默漂移；L8569 的 `>=` 与截断口径相反。

**B. 软告警对 ASCII 密集文件不可达**（R1 抓到的）
- 旧软告警先于硬限可响 ⟺ `b ≥ W/L`；index 需 **2.304 B/字符**，实测 **1.857**（1963 字 / 3645 B）→ 不可达。cwarn 通道（L6629/6632/6731，字节条件）在 index 全区间零触发。

**C. 信号投递粒度 = 每实例一条，且只在会话开始评**（R1 漏掉的，**最贴近本次事故**）
- 注入面提醒受 `maintenanceInjected` 闸（L6850）→ 每实例 1 次；
- 本次事故是**会话中途**把 index.md 写到 2102 字符（实测目录状态），此时该闸早已消费 → 即使软线降到 1800，**该会话也拿不到任何注入提醒**；控制台 cwarn 模型看不见。
- 且 `index.js:4316`（写时闸 `F > b.chars` 硬拒超预算）证明：**2102 字符状态下不可能由 `memory_dream_patch` 通道产出，必然来自一次绕过写**（fs 直写）。→ 事故因果 = 「绕过写」撞上「量纲错致 cwarn 不可达」+「提醒每实例一次」。

## §2 修复范围

### 2.1 模块级同源单一判定源（**先决条件：把 `utf8Bytes` 提级**）

`utf8Bytes` 唯一实现在 **L5939（`apply()` 闭包内，4 空格缩进）**，R1 方案把它放模块级直接调用 = **ReferenceError**；而三处 cwarn 位于 `(async()=>{try{…}catch(e){cerr}})`（L6619~6862）且**早于** L6723 的稳定层注入 → 一抛即该会话**记忆注入整链静默失效**（v2.6.3 同型事故），现行加载门抓不到。

```js
// ① 把 function utf8Bytes(text)（L5939-5944，纯 TextEncoder，无闭包依赖）整块上提到 L1479 之前，删除闭包内副本
// ② 紧随 CHAR_LIMIT/SIZE_WARN 之后新增：
// >>> SIZESTATE BEGIN   （marker 供 new Function 抽取；勿放进 ONBOARD/INT_HASH 区——test/onboard.unit.test.mjs:15 对该区求值，遇 export 即 SyntaxError）
const WARN_CHAR_RATIO = 0.9;      // D1
const WARN_CHAR_CLEAR_RATIO = 0.85;   // 清除线（滞回，见 D1）
function limitOf(key, table) {
  const v = table[key];
  return typeof v === "number" && Number.isFinite(v) ? v : table.summary;   // 防 Object.prototype 键（toString 等）取到函数
}
function warnCharsOf(key) { return Math.floor(limitOf(key, CHAR_LIMIT) * WARN_CHAR_RATIO); }
function clearCharsOf(key) { return Math.floor(limitOf(key, CHAR_LIMIT) * WARN_CHAR_CLEAR_RATIO); }
function sizeStateOf(key, text) {
  const s = String(text == null ? "" : text);
  const bytes = utf8Bytes(s), chars = s.length;
  const byteWarn = limitOf(key, SIZE_WARN), charLimit = limitOf(key, CHAR_LIMIT);
  const warnChars = warnCharsOf(key), clearChars = clearCharsOf(key);
  const overHard = chars > charLimit;                    // 与 L1090/L6050 同口径（== lim 不算超）
  const nearHard = !overHard && chars >= warnChars;
  return { bytes, chars, byteWarn, charLimit, warnChars, clearChars, overHard, nearHard, overSoft: bytes > byteWarn };
}
// >>> SIZESTATE END
// ③ export default 之前加具名导出（gate 取 mod.default 不受影响；onboard 测试只 new Function 该 marker 区）
export { sizeStateOf, warnCharsOf, clearCharsOf };
```

### 2.3 cwarn 文案（旧模板自相矛盾，必须同改）

旧模板 L6630/6633/6732 是 `XXX 超限 3645B（阈值 4608B）` —— 只改条件不改文案会打印「超限 3645B（阈值 4608B）」这种自相矛盾行。新模板：

```
[dsh-memory] index.md 接近硬限：字符 1963/2000（告警线 1800，剩 137）· 字节 3645B（兜底线 4608B），建议精简[会话: <label>]
```

### 2.4 零退化：按规格断言，不再声称「逐字一致」

新条件 = `chars ≥ warnChars || bytes > byteWarn`；旧条件 = `bytes > byteWarn`。
**新版额外告警的字符区间 = `[warnChars, floor(W/b)]`，当且仅当 `b ≤ W/warnChars` 时非空**（`b` = 字节/字符）：

| key | L | warnChars | W | 零退化门槛 `W/warnChars` | 现库实测 b | 现库额外告警区间 |
|---|---|---|---|---|---|---|
| global.md | 3000 | 2700 | 4608 | 1.707 | 2.087（1875/3913） | **空 → 真零退化** |
| index.md | 2000 | 1800 | 4608 | 2.560 | 1.857（1963/3645） | **[1800, 2481] → 提前 682 字符** |
| summary | 1500 | 1350 | 4096 | 3.034 | 1.799（4788/8612） | **[1350, 2276] → 提前 927 字符** |

纯 CJK（b=3.0）：global/index 区间空；**summary 区间 = [1350, 1365]（16 字符，非空）**——1351 个汉字（4053 B ≤ 4096 B）旧版不响、新版响。
→ **诚实表述**：「不改数值 ≠ 不改既有告警时机」。对 global 零退化；对 index/summary 是**按设计提前告警**（提前量 = `floor(W/b) − 0.9L`）；只有 `b ≥ W/warnChars` 的文件逐字不变。summary 自带 1350 字符软线等于部分回退 v9.1「2048→4096B 降噪」决策 —— **这条要用户知情**。

### 2.5 判据修正

「软告警先于硬限可响」的充要条件应写 **`b > W/L`**（等号处软硬同刻，不构成「提前」），且**附加假设「平均 B/字符不随增长上移」**；同文件存在 2~4 种文本派生（raw L6629 / stabilize L6639 / stripCompactionDumps L6731 / stripIntentBlocksForCount L6063）→ `b` 本身**欠定义**，故判据只作趋势论证，不作承诺。

## §3 决策裁定建议（含 R1 的错）

- **D1 软线取 0.9（否 0.85），并加滞回**：index 稳态就在 1900~1970，任何落 (1900,2000] 的软线对 index 都常亮；0.85→1700 让「还剩 300 字符」也报，区分度更差。0.9→1800 的 200 字符带 ≈ 1.7 次本轮观测编辑量（+117）。**清除线 1700**（`WARN_CHAR_CLEAR_RATIO=0.85`），并把该行定性为**状态**而非「整理提醒」。
- **D2 近限信号改挂 `agent/pre-step`（step 1、顶层会话）+ per-rel 水位账本 `NEAR_HARD_NOTIFIED`**：只在「未报 → 已报」跃迁时发一次、降到清除线下复位；解决 §1-C 的「会话中途越限零信号」，同时避免常驻。**R1 的「每会话一条」前提是错的**，按 R1 实现事故场景仍零信号。
- **D3 本版不改 summary 计数口径**（R1 结论对、理由要换）：该口径同时喂养 8288-8294（超限摘要强制入 dream 候选）/ 8574-8576（整合健康）/ `needMaintenanceMerge`+`injectedCharsOf` 体系，属跨子系统改动；本版只在摘要 cwarn 上**只打印字节**。
- **F1 文案与事实不符，本版一并改（限 2 处字符串 + 1 处错误注释）**：全文件无实现「直写通道闸」——唯一 `tools/pre-execute` 是 L7300 的 D 级打转熔断；L8456 的 `toolFilter` 只约束 dream 整合子代理（v2.1.0 起物理移除 write/edit）。实际约束是 DSH 沙箱+审批且可提权越过（与今日三次成功直写一致）。**改 L6481 / L6493 文案 + L6105 注释**（「与通道闸…兼容」亦为假）；**AGENTS.md 不动**（前缀缓存红线，须用户单独拍板）。
- **F2 不提前精简，改完直接重启**：1963 < 2000 是**合规态**，为躲一条提醒删索引指针 = 拿信息换安静。重启后用一次性提醒做真机取证；是否精简另议（且 D2 落地后信号可重复触发，不必赌第一次）。
