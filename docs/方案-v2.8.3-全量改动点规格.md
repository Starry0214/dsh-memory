### A2｜KEEP 白名单纳入 `tool/result`（仅错误）+ 单一来源（对应 L-D）

- **位置**：`L3191-3194`（四类硬编码字符串快筛）／`L3198-3216`（抽取分支）
- **现状**：只收 `user/message`、`assistant/message`、`tool/call`、`compaction/summary`；`tool/result` **整类丢弃**
- **改成**：
  1. 定义**模块级常量 `KEEP_KINDS`**，**同时驱动**本函数与 P1 缓存的收集口径（根因席：现存**不一致**——cache KEEP 含 `system/message`，extractor 四类不含）
  2. 纳入 `tool/result`，**仅错误行**
  3. **错误判据 = `content[].isError === true`**（可写 `data.error != null || content[].isError === true`）
     - 实测：跨 18 个日志查出 **3 例 `isError:true` 而 `data.error === undefined`**（正文均 `Error: sandbox escalation…`）⇒ **`content[].isError` 是超集；绝不可只用 `data.error`，绝不可字符串嗅探**

  4. **`tool/result` 的正文在 `content[].content`，不是 `.text`** ⇒ 抽取路径必须写死（工程席实测）
- **门**：`A10d`（`tool-result-dropped` 变体）

### A3｜`<system-reminder>` 跳过改为「只跳注入块，不跳整条」

- **位置**：`L3201` `if (!txt || txt.indexOf("<system-reminder>") === 0) continue;`
- **现状**：**整条丢弃**。而"跨会话持久记忆自动注入块"**正是记忆内容回灌的载体** —— 用户案例里 `4089b01e` 的 guid 就在这类消息里

- **门**：`A10e`

### A4｜`parts` 类型混装 → 三保险（BUG-2）

- **位置**：`L3187`（推**字符串**标记）／`L3203/3210/3215`（推**对象**）／`L3229`（`arr.map(p=>p.s)`）／`L3241`（`parts.length===0` 守卫）

  2. **另设 `realPieces` 计数**用于 `L3241` 守卫

- **门**：`A1/A2/A3`

### A5｜新增「按类配额预算」（核心新逻辑）

- **位置**：新增，替换 `L3223` 的 `total > maxChars → break`
- **现状**：**FIFO 累加到 maxChars 即 break**；且 `parts.push` **在预算检查之前** ⇒ 单个 piece 可超预算整件保留，**真丢的是它后面的件**
- **改成**（工程席骨架）：
```js
const SHARE     = { compaction:0.35, user:0.45, assistant:0.15, tool:0.05 };  // 未用尽份额可被后到者借用
const PIECE_MAX = { user:2000, assistant:2000, tool:400, compaction:4000 };
const HEAD_KEEP = 200, SLACK = 200;
// used[cls] / totalAll / dropped[cls] 随流式推进
// n = max(0, min(PIECE_MAX[cls], max(quota,0)+SLACK, 剩余全局+SLACK))
// n <= 0 → dropped[cls]++（不 break）
// raw.length > n → 头 HEAD_KEEP + "…[中间 X 字符已截断]…" + 尾 (n-HEAD_KEEP)
```
- **要点**：
  - **禁止"先全收再选"**（单会话最多 6000 万字符，撞内存纪律）⇒ 必须**边流边按类扣配额**
  - **超长件取「尾 + 头」**：6521 字符那条的用户消息，其 9 个 guid 在 **偏移 6115–6441（末尾 580 字符内）** ⇒ 尾部保留**必然覆盖**
  - 配额用尽**不 break**，只 `dropped[cls]++` 并落标注
- **门**：`A10a/A10b`、`A12`（预算不变量）、`A17`（截断标注）

### A6｜截断必须显式标注（独立整行，插在 piece 紧前）

- **格式**：`[⚠ 本条被截断：原文 M 字符，本条保留末 N 字符]`
- **位置**：插在该 piece **紧前**，**不插入 piece 正文内部** ⇒ 正文仍满足"逐字"
- **落点**：与 `note()` 同族（`L3232`），**下游可剥离**；**绝不能让标注随 `unit.text` 被 dream 写进记忆库**
- **必须双数写法**（"截断于 N 字符"三读都通：保留 N／砍掉 N／原长 N）
- **门**：`A17`

### A7｜删除帧采样，改「单遍全帧」（BUG-1）

- **位置**：`L3158`（`FULL = sizeMiB < 8 || frames ≤ 12`）／`L3162-3168`（K 采样）
- **现状**：K 按**文件大小**缩放（1.5 帧/MiB），而帧数 ≈2700 帧/MiB ⇒ 9 MiB 会话只选 **18/24860 = 0.072%**
- **改成**：
  1. **删掉 `K`/`selected` 三分支采样**，**单遍遍历全部帧**
  2. `FULL` 语义收窄为**仅 `≤12 帧`的微型会话 sanity**（消除"一句取消 FULL、一句保留 FULL"的自相矛盾）
  3. **保留 `L3157` 的 `frames.splice(0, skipFrames)`**（水位语义依赖它）
  4. **全局帧号 = `skipFrames + i`**（marker 里的总数用 `skipFrames + frames.length`）—— 否则增量档坐标/标记全错位
  5. **每 64 帧让出**：`if (i > 0 && (i & 63) === 0) await new Promise(r => setImmediate(r));`（全帧化后 8.6 万帧，逐帧让出会成为瓶颈）
- **★ 必须同时加墙钟预算**：`L6809` 注释逐字写着「此处 await 只到『提取+发起完成』（**秒级**）…（实证旧路径一晚上把会话启动顶住 **6 分 14 秒**）」，`MAX_ARCHIVE_SESSIONS = 32`（`L4672`）⇒ **全帧化打破这个被显式依赖的假设**。二选一：**(a) 给提取阶段加墙钟预算并明确降级行为**，或 **(b) 改为不 await（真正后台）**
- **门**：`A4`（全帧覆盖，预算不 binding 夹具）、`A5`（帧口径冻结）、`A14`（skipFrames 语义）、`A18`（让出节奏）

### A9｜`UNIT_MAX_CHARS` 与桶预算的不变量

- **位置**：`L3266` `UNIT_MAX_CHARS=20000`／`L3267` `BUCKET_BUDGET_CHARS=60000`／`L3268` `BUCKET_MAX_UNITS=5`

## §5 C 组：原文检索 CLI（新文件，零插件改动）

### C1｜布局

```
~/.dsh/tools/session-search/{session-search.mjs, README.md}
~/.dsh/session-text/<sid归属日>/<完整uuid>/{manifest.json, seg-000N.jsonl}
```
- **★ 段列表只许来自 `manifest.json`**（若检索侧用 glob `*.jsonl`，**重建后的孤儿段会被 rg 搜到 → 返回过期正文**）

- **★ 段数有界 + 滚动合并**（上限 **16**）；**合并后同一 `(f,s)` 取段号最大者**（解决"扫到即停"冲突）
- 缓存**不放** `~/.dsh/memory/`（否则被 `scanUndisposed`／检索候选集／面板统计／预算告警扫到）

### C2｜收录口径（`KEEP_KINDS` 单一来源，与 A2 同源）

| 类型 | 收 | 抽取路径 |
|---|---|---|
| `user/message` | ✅ | `data.content[]` 中 `type==="text"` 的 `c.text` |
| `assistant/message` | ✅ | `data.message.content[]` 中 **`filter(c => c.type === "text")`** |
| `system/message` | ✅ | 同 assistant 路径 |
| `tool/call` | ✅ | `data.name` + `data.arguments` |
| `tool/result` | **仅错误** | **正文在 `content[].content`，不是 `.text`**；判据 `content[].isError === true` |
| `compaction/summary` | ✅ | `data.summary[]` 中 `type==="text"` |
| chunk 四类 / `request/header` / 其余 | ❌ | — |

**四处写死**：①错误判据（见 A2）②`assistant/message` 必须 `filter(type==="text")`（**`reasoning` 块也带 `text` 字段**，naive `map` 会吞进 reasoning 全文；实测 **48 条中 12 条（25%）无 text 块** ⇒ 需单独计数"类内空正文"）③两条路径不同（`user/message` → `data.content[]`；`assistant/message` → `data.message.content[]`）④**`compaction/summary` 无实测覆盖（两席样本均 0 条）⇒ 门必须专门造夹具**

### C3｜缓存行格式

```json
{"k":"_meta","ver":1,"sid":"<完整uuid>","files":[…],"built":"…","dropped":{…}}
{"t":1789006838082,"k":"user/message","s":9,"f":"session.jsonl.zstd","x":"…逐字…"}
```
一行一事件；换行**交给 `JSON.stringify` 单次编码**（**禁手工二次转义**）；`x` **逐字**、不截断/不改写/不脱敏；`f` 标物理文件；`s` = **源帧序号**（不是缓存行号）。

### C4｜身份键与归并

- 一个 sid 收目录下**全部** `.zstd`（不是两个已知名字 —— 否则 DSH 再改名成 v4 会**静默漏收第三个文件**）
- **身份校验**：解码帧 0，其 `session` 头 `session.id` 必须等于目录 sid
- **★ 不符时：中止该 sid 并记 `.build-errors.log`（路径/格式/不轮转/明确不在 R8 扫描面内），继续其他 sid，报告单列**
- **★ 文件序 = `mtime` 升序**（7/7 劈开案例只靠 mtime 不重叠才成立）
- **主排序键 = `(文件序, 帧序, 帧内行序)`**；`time` 仅展示 + overlap 校验
- 两文件 `time` 区间重叠 → **报 `overlap` 并中止该 sid**

### C5｜水位（`lastFrameOff` 起始偏移）

```jsonc
{ "name":"session.v3.jsonl.zstd", "size":1234567, "frames":4734,
  "lastFrameOff":1046520, "lastFrameDigest":"sha256:<前16>", "badOffsets":[…] }
```
- **★ Node zstd API 不返回"本帧消费了多少字节"** ⇒ **拿不到帧结束偏移** ⇒ 水位**只能是"最后一个已消费帧的起始偏移"**；续跑 `offs.findIndex(o => o > lastFrameOff)`。**写 `+4` 会重复命中同一帧 → 重复行**
- 续跑**先验** `digest(decompressFrameAt(buf, lastFrameOff)) === lastFrameDigest`（不符 → 全量重建）
- 三条约束：①"起始偏移"非"已消费字节数"（后者半帧处**二义**）②**失败/残帧不得推进偏移** ③偏移**检不出"同尺寸原地重写"** ⇒ **另配 `size` + `mtime`**
- **伪 magic**：`scanZstdFrames` 逐字节扫，压缩体内可能出现伪 magic → 返回 null。若当"停下、下轮再来"则**水位永不前进** ⇒ **必须 `continue` 并记入 `badOffsets` 让水位越过**

### C6｜原子性与并发

段文件**写一次永不修改**；`manifest.json` **唯一可变点**，`tmp → rename`；**不用"增量=重写整档"**（只省 CPU 不省 I/O）；**Windows `rename` 撞 `rg` 读取可能 `EPERM/EBUSY`** ⇒ 重试退避 + 门覆盖。

### C7｜检索与输出（两个 P0 级不变量）

- **不变量 A（坐标源侧化）**：输出坐标带标签 `cache:#1204` / `src:<file>#f12@0x1A3C`；`--show` **接受源坐标**并还原；**扫全部段但按 `f`+`s` 匹配、扫到即停（合并后取段号最大者）**；**坐标失效（重建后）时显式报"已失效，请改用关键词重搜"，绝不返回邻近/空白**；**以帧号为准**，字节偏移仅辅助
- **不变量 B（截断不冒充命中数）**：先 `rg --count` 拿总数，**永远打印"命中 N 处（其中列出 M 条）"**，JSON 里 `total ≠ listed`
- **零结果引导**：显式声明「**0 结果 ≠ 没记录**」+ ①换更稀有的词②放宽 `--since`/去掉 `--kind`③**缓存可能滞后**
- **`rg` 缺失**：**实测不在 PATH**（二进制在 `@deepseek-ai/dsh/node_modules/@vscode/ripgrep-win32-x64/bin/rg.exe`）⇒ 工具**自行定位**；缺失时**显式报错 + 非零退出，绝不报 0 命中**

### C8｜`--replay`

- `--since/--until` 按**事件 `time` 本地时区**，**闭区间 `[since 00:00:00.000, until 23:59:59.999]`**（两端都含当天）；另给 `--by-dir`（按目录归属日）
- 只列 `user/message`（全库 ~2.7%），按时间铺出

### C9｜内存纪律

逐帧即弃（**禁 `Buffer.concat`**：实测同一 27.27 MiB 日志 concat **maxRSS 922.9 MB** vs 逐帧 **211.5 MB**）／直写磁盘／**检索在进程外**（脚本永不把语料读进内存：124–149 M 字符 → UTF-16 **248–298 MB 堆常驻**）／一次一个 sid。

### C10｜root 覆盖（门的**前置**）

`--sessions-root` / `--cache-dir` / `DSH_HOME`，否则 R1–R21 只能污染真库（1079 文件 / 713 MiB）。
