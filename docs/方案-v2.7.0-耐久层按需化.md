## 2. 关键决策：存储形态（回应"向量库？或者类似 mimocode 的数据库？"）

### 2.1 实测：mimocode 用 SQLite **FTS5**（关键词），不是向量库

| 文件（两个 checkout 并存，`memory/service.ts` sha16 **完全相同** = `9CEAC82A7C02F17A`） | 事实 |
|---|---|
| `packages/opencode/src/memory/fts.sql.ts` L3-19 | `memory_fts` 表：`id/path/scope/scope_id/type/body/fingerprint/last_indexed_at` + `scope_idx`/`type_idx` |
| `.../memory/service.ts` L102-121 | `FROM memory_fts_idx MATCH ?` + **`bm25()`** + **`snippet()`** = SQLite FTS5 |
| `.../memory/service.ts` L39 / L46-50 | `root = Global.Path.data/memory`；检索前 `reconcileMemory` **扫记忆目录的文件**建索引 → **Markdown 是源真相，SQLite 只是可重建派生索引** |
| `.../memory/reconcile.ts` L100-120 | 只删「盘上已不存在」的 FTS 行，不删文件 |
| `.../session/checkpoint-templates.ts` L78 / L109（⚠ 在 `session/` 不在 `memory/`） | 耐久知识本体仍在 Markdown：`## Discovered durable knowledge`，预算 4000 |
| 全 `memory/` 目录 | `embedding\|vector\|cosine\|semantic\|faiss\|pgvector` = **0 命中**（全仓 16 处命中全无关，`vectorStoreIds` 在 Copilot provider SDK 透传里） |

**结论：mimocode 的"数据库"是检索加速器，不是向量库；它的记忆源真相同样是文件。**

### 2.2 我们的现状已是同一形态（只缺 SQLite）
源真相 = Markdown（可 grep / diff / 手改 / git）；检索 = `scoreTarget` 纯 JS TF 打分（抄了 OR 分词 + 相对下限，并补 `ABS_MIN_SCORE` 修中文虚词噪声）；索引 = **每次现读扫盘**（无缓存 → 无"索引陈旧"故障类）；分发 = 单文件零依赖。

### 2.3 为什么现在不该上向量库
1. **召回形态不匹配**：耐久层首要内容是**精确字面量**（编号/合同号/路径/命令），embedding 恰在低频串上最弱，关键词最强。
2. **它不解决真问题**：痛是"**想不到去看**"（注意力），不是"找不到"（召回）；向量库是 pull-only 的极致，比 Markdown **更 pull**。⚠ **证据席指出此条纯推断、当前不可证伪** → 降级为**待测假设**，D4 的观测源正是为它准备的判据。
3. **新代价与新失败模式**：插件零网络零依赖离线可用；embedding 要么调 API 要么内置模型，"模型不可用=记忆不可读"是全新故障类。

> **重启此话题的判据**（D4 落地后）：出现可测的"关键词查过、语义近邻本应命中的事实漏检"失败率。

### 2.4 该借鉴的（结构，不是换库）
`scope`/`type` 维度打标；**文件与索引分离**（索引永远只能派生，不得成为唯一真相）；可重建 + fingerprint 幂等（我们的现读扫描天然满足）。
