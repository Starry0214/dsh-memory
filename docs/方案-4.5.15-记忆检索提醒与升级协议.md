## 0. 背景：MiMo 的三层做法

| 层 | MiMo 做法 | 效果 |
|---|---|---|
| **每轮提醒** | 每条用户消息前，若 `hasMemoryOrTasks(sid)`（会话 memory 目录非空 或 task 有记录）⇒ 向**最后一条 user message** 追加 synthetic `<system-reminder>`：本会话记忆路径 + `memory search` + `Read` + `task list` + `actor status` + “Don't ask the user about something memory may already record.”（~120 tok/轮，仅尾部、前缀缓存零影响） | 压缩/重建后跨多轮保持“先 recall 再问人”的反射 |
| **升级协议** | `memory` 工具描述写死：A HIT IS AUTHORITATIVE / PARTIAL HIT→`history` 取逐字原文 / 0 命中逐级升级（换稀有词→Grep→history）/ scope 逐级 session→project→global→history；`history` 工具描述：“USE ONLY WHEN MEMORY SEARCH RETURNS NOTHING USEFUL” | 模型知道“什么时候换通道、什么时候别放弃” |
| **重建注入** | `renderRebuildContext` 注入 `<system-reminder>Verify-before-act…` + Accumulated learnings + Current snapshot | 压缩后先看到“之前学到什么”，且被要求验证再行动 |

## 2. Part A：每轮条件 recall reminder

### A1. 触发条件（等价 MiMo 的 hasMemoryOrTasks）

在 `agent/pre-step`（step===1、顶层会话、真实用户消息）判定 `hasRecallTarget(sid)`，任一为真：
1. 本会话已有检查点（P2.5 会话主题存在，或 `.monitor.json p3.sessions[sid].checkpointAt` 有值）；
2. 本会话笔记主题存在且未提炼句 > 0（`noteUnrefinedCount`）；
3. 本会话当前注入面包含记忆切片（启动注入过 stable layer / 最近摘要）。

**否定条件**：子代理（`isSubagent`）、非 step1、上一条 user 消息是 synthetic、本轮已注入过 recall reminder、flag 关。

### A2. 注入文本（目标 ≤180 字，约 120–160 token）

```
<system-reminder>
【记忆检索】本会话有可召回记忆（检查点/会话笔记/主题库）。需要时：
- memory_search("<稀有词>") → 命中后 memory_read <主题ID/名字>
- 原文细节/逐字字面量 → session_search("<精确串>")（命中后 show 回看）
纪律：命中即信（别因换词没命中就断定没记录）；摘要可能丢字面量，取逐字原文；0 命中按「换稀有词 → memory_topics 直查 → session_search → 放宽范围」逐级升级；不要问用户记忆里已记过的事。
</system-reminder>
```

- 渲染进 `enter.messages` 尾部（与 A 类提醒同机制），**不改会话历史、不写 inbox**；
- 若本轮 A 类提醒/回归提醒也命中：**合并为一条** system-reminder（先 A 类后 recall 协议），避免两条尾部提示；
- 节流：同一用户消息只注入一次；同一会话 2 分钟内最多一次（防连续工具步骤重复）。

### A3. 开关与观测

- flag `recallReminder`（默认 true）：`DEFAULT_CFG` + `SETTINGS_SCHEMA` + `normalizeCfg` + `WRITABLE` + 热更新；
- `monitorEvent("recall","inject sid8=… chars=… merged=a|r")`；`p3CostBump` 记 `recall-inject`（tokens 估算可选）；
- 关闭时零字节注入（门断言）。

## 3. Part B：升级协议写进工具描述

### B1. `memory_search` 描述追加（对齐 MiMo 三段式）

```
使用纪律：
- 命中即信：一次命中就是证据，别因换个说法没命中就断定"没记录"。
- 摘要可能丢字面量（端口/路径/命令/ID/文号）：需要逐字原文时用 session_search 取原文，不要从摘要猜。
- 0 命中时逐级升级：换更稀有词 → memory_topics 看结构/memory_read 直读 → session_search 原文 → 放宽范围（本会话笔记→项目主题→全局/跨项目）。
```

### B2. `session_search` 描述追加

```
仅在 memory_search 无有用结果、或需要逐字原文时使用（原文检索是"更慢但逐字"的通道）：
- query 用最稀有的精确串（GUID/URL/完整路径/报错串），不要用描述性长句；
- 命中后用 show 回看上下文；日志轮转缺失时用 source:"units"。
```

### B3. 门

- 静态断言：`memory_search` 描述含「命中即信」「session_search」「逐级升级」；`session_search` 描述含「仅在 memory_search 无有用结果」；
- 不改工具参数/返回结构（纯文案），零行为风险；`memory_size_preview` 等不受影响。

## 4. Part C：重建注入增强（R2）

在现有 `buildPostCompactRehydrate` 文本上追加/调整（flag `rebuildLearnings` 默认 true）：

1. **Verify-before-act 提醒**（首行，~40 字）：
   `记忆可能过期：动手前先用 memory_search/memory_read 验证相关结论；与当前代码/用户最新说法冲突时以现状为准。`
2. **Accumulated learnings**（新增，bounded ≤800 字）：取最近 **2–3 个**会话检查点主题的「关键结论」「错误与修复」两节摘录（每检查点 ≤2 条、每条 ≤120 字），去重后按时间正序排列；不足 2 个则只放现有 1 个。
3. **Current snapshot**：保持现有最新检查点全文（预算不变）。
4. 预算：新增 ≤900 字（verify 40 + learnings 800 + 标签），总注入预算在原 R2 上限内（超则先砍 learnings 再砍摘要）；flag 关时 R2 文本 **sha16 与 4.5.14 逐字一致**。

门：
- 真库副本 fixture（≥2 检查点）⇒ 注入含 verify 提醒 + ≥2 检查点的 learnings 摘录 + 最新 snapshot；
- 只有 1 个检查点 ⇒ learnings 降级（不报错）；
- 预算上限断言；flag 关 sha16 == 基线。

### 9.1 L-1 R3 关系重写（K-2 阻断项，解）
- **删除** §8.2 的「recall 成功 ⇒ 跳过 R3」跨通道判定（时序不可实现：R3 在 `turn/start` 决策，早于同轮 step1 pre-step）。
- **新机制**：`turn/start` 只维护 `st.turn` 计数（不再判 R3 到点）；把 R3 到点判定**挪进同一个 pre-step handler**：
  1. 先判 recall（L-5 条件）→ 命中则 append recall 文本，**本轮 R3 跳过**；
  2. recall 未命中且 `st.turn - st.lastNudgeTurn >= 8` → append R3 文本（同一通道，不再走 `agent.inject`），**append 成功后**才置 `lastNudgeTurn = st.turn`；
  3. 两者都不命中 → 不注入。
- 账本统一为**轮次**（`st.turn` / `st.lastNudgeTurn`，持久化在 `p3.sessions[sid]`）；`recallNudgedAt` 仅作观测，不参与判定。

### 9.2 L-2 handler 纪律
