## 五、本次取证的自我评价（如实）

**同一个错误（读错返回字段）我犯了四次**，且每次都"看起来得到了 Self-consistent 的结论"：
- 第 1 次（`_audit-103-orphans`）报"103 个全无正文、不必救" ⇒ 我因"27 MB 日志却 0 字不合理"而**没接受**
- 第 2 次（`_reaudit`）报"70 个 product 判无正文" ⇒ 我**接受了**，并写进文档与记忆
- 第 3 次（`_quantify-chunks`）报"47 个 / 266万字 chunk 漏档" ⇒ 我**接受了**，还建了整份取证文件
- 第 4 次（`_recheck-flow`）仍报"70 个 flow=0" ⇒ 我**仍在接受**，直到执行 B7 时插桩才撞破

**教训（比结论更重要）**：
1. **读第三方返回值前，必须先打印它的键**。我四次都在"假设字段名"上栽倒，且第一次的反证（43eaa05d 有 43826 字）
   我当时归因成"传参类型错"，**没有进一步问"为什么同一个函数会有两种形状"** —— 停在了浅层原因上。
2. **一个自洽的数字不等于正确的数字**。266 万、41 万、75 万都能自圆其说，因为错的口径会稳定地错。
3. **"不可能的数字"是唯一可靠的警报**：我第一次拒绝接受"27 MB 日志 0 字"，是对的；
   但后来接受了"2 MB 日志 0 字"，**没有追问差异** —— 同一类异常只警觉了一次。
