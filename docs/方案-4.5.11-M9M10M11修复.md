## 1. 目标 / 非目标

### 目标

1. **M9**：T4 压缩检查点写失败后，T5 的会话收尾补写**仍可用**；同时不破坏「T4 在途期间 T5 不重复写」的既有抑制。
2. **M10**：T1 阈值检查点 cid 每会话唯一（`p3t<level>-<sid8>-<b36>`），不再有同毫秒跨会话撞键风险。
3. **M11**：重试补火的检查点写入**目标会话的工作区线**（而不是触发者工作区），消除跨工作区线污染与桥接注入。

### 非目标（避免扩大面）

- 不改 T5 已完成的逻辑（只把 `hasCheckpoint` 判据从「单字段」扩展为「成功标记 + 在途标记」）。
- 不改 `p25ReadPreviousSession` 的读侧逻辑（M11 只修写侧归属；读侧行为回归由门禁覆盖）。
- 不改重试队列的调度策略（退避/熔断/次数不变），只加 cwd 字段与 parent 选择。
- 不改 4.5.10 已交付的 label / 三态记账 / 归档过滤 / cid 纯函数。

## 2. 逐项设计

### M9：T4 `checkpointAt` 预置 → 改为「在途标记 + 成功标记」

**根因**：`checkpointAt` 一个字段同时承担两种语义——「已有检查点（成功）」与「检查点正在写（在途）」。T4 在 spawn 前就写它，失败后无清理 ⇒ 语义永远停在「成功」。

**修法（最小状态扩展）**：

1. `p3SessionState` 默认对象增加 `checkpointPendingAt: 0`（`index.js:5817` 附近；旧 `.monitor.json` 条目缺字段按 0 处理）。
2. `index.js:18264`：`_p3st.checkpointAt = Date.now()` → **`_p3st.checkpointPendingAt = Date.now()`**（`lastActivityAt` 保留）。
3. `spawnIntentCheckpoint` 成功路径（db 分支 `index.js:15290` 附近、md 分支 `index.js:15345` 附近）：把现有 `p3MarkT5CheckpointDone(compactionId, sessionId)` 改为**通用** `p3MarkCheckpointDone(sessionId)`——`checkpointAt = now; checkpointPendingAt = 0; lastFireAt = now`（不限 cid 前缀；T5 的 `p3e-*` 也走它，4.5.10 MF2 语义保持）。
4. T4 spawn 处（`index.js:18289` 之后）：给 `_pW` 挂失败清理——
   `_pW.then(res => { if (!res || (!res.ok && !res.duplicate && !res.queued)) { const st = p3SessionState(session.id); if (st) st.checkpointPendingAt = 0; } })`
   （`queued` 保留 pending，等队列补火成功回填；最终失败清 pending ⇒ T5 可补写。不改变 `P4C_INTENT_WAIT` 的既有等待语义。）
5. T5 sweep 的 `hasCheckpoint` 判据（`index.js:21363`）：
   `!!st.checkpointAt || (Number(st.checkpointPendingAt) > 0 && now - Number(st.checkpointPendingAt) < T5_PENDING_TTL_MS)`
   新增常量 `T5_PENDING_TTL_MS = 30 * 60e3`（= 2 × `SUBAGENT_HARD_MS` 15min；`index.js:14028`）。pending 过期 ⇒ 视为无检查点（防崩溃窗口永久阻塞 T5）。

**兼容**：旧条目无 `checkpointPendingAt` ⇒ 0；`checkpointAt` 语义收敛为「成功标记」，历史数据不受影响。
**G-9**：`.monitor.json → p3.sessions[*]` 新增 `checkpointPendingAt`；T4 不再在压缩瞬间写 `checkpointAt`（改为写成功时）。
**验证**：`__p3Hooks` 暴露 `pendingActive(st, now)` 纯函数（或 `checkpointKnown(st, now)`）；门测：pending 未过期 ⇒ hasCheckpoint true；过期 ⇒ false；成功标记后 pending 清 0。

### M10：T1 cid 唯一化

**根因**：同 T5（`sid.slice(0,8)` 恒 `"session-"`）；跨会话唯一性只靠 `Date.now()` 毫秒。

**修法**：

1. `index.js:21314`：`const sid8 = sid.slice(0, 8);` → **`const sid8 = sid8Of(sid);`**（4.5.10 模块级 helper，`index.js:6968` 附近）。
2. 抽纯函数 `p3ThresholdCid(level, sid, now)`（`"p3t" + level + "-" + sid8Of(sid) + "-" + Number(now).toString(36)`），`index.js:21317` 改用它；`__p3Hooks.thresholdCid` 暴露供门测。
3. 注意：`p3SessionState(sid)` 的键仍是**完整 sid**（不变）；只有 cid 用 sid8。

**兼容**：旧 meta 键 `intent:p3t1-session--*` 残留无害（新 cid 不撞）；旧 md marker 正则 `[0-9a-zA-Z-]{8,}` 仍匹配新 cid；重试队列旧条目（旧 id）仍可补火（id 只是键）。
**G-9**：T1 检查点首行 cid8 从 `p3t1-ses` → `p3t1-<sid8前4>`（长度不变）。
**验证**：门测 `p3ThresholdCid` 唯一性/格式/不含 `session-`；静态断言 `index.js:21314` 不再 `sid.slice(0, 8)`。

### M11：重试队列持久化目标 cwd + 目标父会话选择

**根因**：重试条目只存 `fname/sid/text/sessionId`，不存 cwd；补火时把「触发者 agent」当父，`spawnIntentCheckpoint` 从它取 cwd ⇒ 写错工作区线。

**修法**：

1. `intentRetryEnqueue(compactionId, fname, sid8, text, sessionId, reason, cwd)`（`index.js:13259`）：entry 增加 `cwd: String(cwd || "").slice(0, 512)`。
2. `intentRetryFail(..., reason, cwd)`（`index.js:15151`）增参；6 个调用点（`index.js:15212/15221/15226/15235/15314`）传 `_targetCwd`。
3. `spawnIntentCheckpoint`（`index.js:15171`）开头计算目标 cwd：
   `const _targetCwd = String((opts && opts.cwd) || "") || cwdFromAgent(parentAgent) || cwdFromAgent(agentsBySession.get(sessionId)) || "";`
   `_cwP25` 改为 `_targetCwd`（db 分支不再从 parentAgent 现取，`index.js:15255-15262` 简化）。
4. `fireIntentRetry`（`index.js:13297`）：改为
   `spawnIntentCheckpoint(e.id, e.text || "", e.fname || (dateStr(new Date()) + ".md"), null, e.sessionId || "", { retry: true, cwd: e.cwd || "" })`
   ⇒ `pickSpawnParent(null, sessionId)` 优先用**目标会话**的 live agent 作父（归档/无 live 时按既有顺序回落；4.5.10 起 label 已带目标 sid，可读性兜底）。
5. 旧条目无 cwd 的兼容：`_targetCwd` 走 `agentsBySession.get(sessionId)` 的 cwd；仍空 ⇒ `topicDbIntentRoute` 空 cwd 回落 D8 日期主题（不是错误路径），并 `monitorEvent("intent","retry-cwd-missing "+id8)` 留痕。

**风险/边界**：`parentAgent=null` 时 `compactOnce` 的 `pickSpawnParent(null, sessionId)` 与 `pickSpawnParent` 的 null 语义（已支持）；`_cwP25` 空串时 p25 会话主题跳过、回落日期主题；`intentRetryHas` 去重键不变。
**G-9**：重试检查点落库的**主题线归属**从「触发者工作区」改为「目标工作区」；`.integrate.json intentRetry[*]` 新增 `cwd` 字段。
**验证**：门测 cwd 解析纯函数 `p3ResolveTargetCwd({optsCwd, parentCwd, sessionCwd})`（`__p3Hooks` 暴露）；静态断言 `fireIntentRetry` 传 `cwd` 且 parent 为 null；真机重启后观察重试写入目标线。

### 9.2 MF1–MF9 落实规格

- **MF1**：`p3T4PendingCleanup(sid, res, reason)` 统一清理——仅终态失败（`!res || (!ok && !dup && !queued && !retry)`）清 `checkpointPendingAt` + `scheduleMonitorSave()` + `monitorEvent("p3","t4-pending-cleared reason=…")`；挂 T4 `.then`、两处 queued 重火（`15066`/`15320`）、`INTENT_PENDING` 淘汰（清被淘汰会话的 pending）。
- **MF2**：`T5_PENDING_TTL_MS = 60*60e3`（注释写推导）；T5 判据 `hasCheckpoint = !!checkpointAt || pendingActive(st, now)`；`pendingActive` 纯函数入 `__p3Hooks`。
- **MF3**：`p3MarkCheckpointDone(sessionId)`（通用，无 cid 前缀判断）替换 `p3MarkT5CheckpointDone`；db 成功（`15269`）、md 成功（`15303`）、md dup 早退（`15218`）三处调用；同步改 `_test-t5-fix.mjs` B9/B10/S8（B10 改为「非 p3e 也回填（M9 语义）」、S8 匹配新函数名），方案显式声明。

- **MF5**：`cwdFromAgent(a)` 纯函数（上述四路兜底，`null`→`""`），入 `__p3Hooks`；静态断言不出现单路 `a.header.cwd || a.cwd`。
