## 1. 约束（本模式特殊性，必须逐条满足）

1. 真源 = 主题库 mem.db；导出视图 md 禁读；dream 只能 `memory_read/memory_search`。
2. 笔记主题 `笔记·<wsKey>/<sid8>` append-only：dream 不能直接写，只能哨兵 JSON 收敛。
3. 检查点主题 `<wsKey>/<sid8>` 恒 1 句覆盖：**dream 只读**，v2 用代码护栏保证（M-3）。
4. 写入只走 `memory_dream_patch`（CAS/审计/批量原子/容量三档）。
5. 每轮上限：split 2 / review 6 / rename 3 / 卫生 3；候选 token 预算有界。
6. 库模式 vs md 模式隔离：新逻辑只在 `TOPICDB.enabled` 分支；md 路径逐字不变（sha16 基线）。
7. 既有护栏：单管线互斥、guard 15/25min、失败 2h 重试、空轮判定、健康体检、`overLimitStuck`。
8. **新纪律**：预筛只做"线索"，任务书必须写「预筛关联是线索不是结论；与其判断冲突时以 memory_read 为准；**不得仅凭预筛关联做 merge**」（S-2，merge 归档源主题不可逆）。

### A1. note → 关联主题（内存打分，**不调检索函数**）

**实现**：`index.js` 新增 `dreamPrescreenNoteLinks(rows, noteRows, opts)`；在 `buildDreamPromptLibrary()` 内、`_allRows`/`_noteRows` 已取之后调用（零额外全表扫描）。

**算法**：
1. **输入**：未提炼笔记主题（`noteUnrefinedStats`，口径 A），按未提炼句数降序取 **≤6** 个。
2. **摘录（M-2）**：每 note 取未提炼句，**单句先截断到 ≤200 字**，最多 2 句、累计 ≤400 字；0 句 ⇒ `fallback:"no-snippet"`（不是空摘录静默）。
3. **输入清洗（M-5）**：剔除结构标签（`quote/literal/observation/用户原话/★`）、日期、纯数字、单字、长度 <2 的中文 token；英文/路径/ID 保留（≤64 个 token 硬上限）。
4. **打分（内存，无 SQL LIKE、无 `topicDbSearchTopics`）**：
   - **第一层（零额外读库）**：`_allRows`（`store.topics()`）每行已带 `name / state / sentences / chars / updatedAt / activeTriggers / effectiveTriggers / genericTriggers` ⇒ 在 **主题名 + effectiveTriggers** 上统计 token 命中（排除 genericTriggers），O(主题数 × token 数)。
   - **第二层（有界细化）**：取第一层 top 10 候选，`store.readTopic(id)` 读正文，在**句子文本**上复核命中（仅 10 次读，非全表）；无正文命中则降权。
   - `score = Σ(命中 token 权重) / (1 + log(1 + topicChars))`（长度归一，防大主题霸榜）；同 token 的 df 用第一层「命中该 token 的主题数」估计 ⇒ `×log(1 + N/df)`（N=非归档主题数）。
   - 命中来源标注（S-4）：命中的 token 列表 ≤3 个（如 `T5/检查点`）。
5. **输出**：每 note ≤3 个关联主题（id、名字、句数、状态、摘要：前 2 句各 ≤80 字）；无命中 ⇒ `fallback:"no-hit"`。
6. **兜底（D-4）**：**不新增第三份列表**；`otherPick` 保持现状 10 个不变；预筛块只写一行「若本条无强关联，允许在下方候选主题里找归属」。
7. **预算（D-1 定稿）**：`每 note ≈ 摘录 ≤400 + 3×(元信息 45 + 摘要 80) ≈ 775 字`；6 note ≈ 4,650 → **预筛块 ≤4,500 字（超出截断到 note 级）**；**任务书总字符 ≤8,500 字**（骨架 ≈3,919 + 4,500）。双上限门禁（G4）。
