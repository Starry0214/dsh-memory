## D-1｜P0 扩范围：新增 BUG-3「三处每件上限」（**本轮最重要**）

**新增事实（实测）**：`extractMessageFlowAsync` 有三处**每件固定上限**，v2.8.1 完全没有提及：

| 位置 | 现值 |
|---|---|
| `L3202` 用户消息 | `txt.slice(0, 800)` |
| `L3209` 助手消息 | `txt.slice(0, 1000)` |
| `L3213` 工具参数 | `String(args).replace(/\s+/g," ").slice(0, 80)` |

**证据（`_probe-trunc800.mjs`，逐字复刻 `L3200` 的算法）**：
- `62c8532e`（用户自己贴的知识库 guid 清单）：`txt` = **6521 字符** → `slice(0,800)` 保留 800，**砍掉 5721（88%）**
- 该消息里 **9 个 guid 全部位于偏移 6115–6441** ⇒ **9/9 全被砍，一个都没进归档子代理的视野**
- `9b865459`（子代理 prompt，41961 字符）：guid 位于偏移 14794–15580 ⇒ 同样全被砍

**⇒ 用户"记忆里只有前缀"的真身是 `slice(0,800)`，不是帧采样。** v2.8.1 只修帧采样（BUG-1）与 `parts` 混装（BUG-2），**修完用户痛点不会消失**。

**拟修法（待审）**：改为**全局预算 + 件内保尾**；且**产物必须标注"本条被截断于 N 字符"**。

## D-2｜新增 BUG-4「天花板裁决」（v2.8.1 缺失）

| 层 | 现值 | 问题 |
|---|---|---|
| `extract` 层（`L3170`） | `maxChars = sizeMB < 5 ? 8000 : 200000` | `<5 MB` 档 **8000 过低**，而 `<2 MB` 桶是**最大群体（136 个会话）** |
| `compressUnit`（`L3266`） | `UNIT_MAX_CHARS = 20000` | 修完 extract 顶到 200000，此处**二次截断** ⇒ 净收益 **60× → 6×** |

**配套新增门 A8**：目标字面量放在**第 61 个工具行** → `unit.text` 仍须含它。

## D-3｜新增 §2.5「账本修复」（v2.8.1 缺失）

**核实（主代理实测 `.integrate.json`）**：
- `archivedSessions` = 280 条（格式 `session-<uuid>`）；`archiveWatermarks` = **280 条（是数组**，条目 `{id, frames, round, at}`）
- **177 / 177 个单元都在 `archivedSessions` 中**；**2 个空产物（`60e0713f` / `da1a1bf8`）已被消号**

**机制**：`unit.text` = 17 个换行是 **truthy** ⇒ 通过 `L5811 if (unit && unit.text)` ⇒ `ARCHIVED_SESSIONS.add` + `ARCHIVE_WATERMARK.set(id,{frames:cur})` ⇒ `archivePendingEntry`（`L3435-3448`）的 `cur > wm.frames` **恒 false ⇒ 永不再归档**。

**⇒ "清空 `.archive-units/` 重跑"不足以恢复。拟步骤**：①筛出"去标记后为空白"的 sid ②从 `archivedSessions` 摘除（或 `archiveWatermarks[id].frames` 置 0）③清空单元缓存 ④重跑 ⑤先备份 `.integrate.json`。

## D-4｜`§2.3` 改为「单遍全帧 + 尾部环形缓冲」

**推翻 v2.8.1 的"两遍扫描"**：其成本模型错——pass 1 的快筛作用在**解压后文本**上 ⇒ **必须解压全部帧**，总计 ≈1.0–1.1×，不是"多一遍 4.6 s"；且两遍会把同一 KEEP 谓词**抄两处**（`L3191-3194` vs pass-1）。

**新写法**：①删 `K`/`selected`/FULL 三分支采样，**单遍遍历全部帧**（`FULL` 只留 `≤12 帧` 微型会话做 sanity —— 消除"一句取消 FULL、一句保留 FULL"的自相矛盾）②提取到 piece 即 push + 维护**尾部环形缓冲（40K 字符）**③`total > maxChars` **不 break**，只置 `truncated` 并停止头段累加 ④组装 = 头段 + 尾缓冲 + `note()` ⑤**每 64 帧让出一次**（现为每帧 `setImmediate`，全帧化后 8.6 万次）。

**新增：预算分配规则**（现行代码自相矛盾：messageflow `L3223 break` **保头**，compaction `L3238 slice(-maxChars)` **保尾**）⇒ 写死：**压缩摘要 > 用户 > 助手 > 工具，同级新近优先；messageflow 分支改保尾**。

## D-5｜BUG-2 修法改「三保险」+ 不变量（根因席意见）

`kind` 方案两处漏洞已按评审改：**"建议"→必填**；`p.kind !== "marker"` **fail-open**，非白名单。

**三保险**：①标记**另存 `markers` 数组、不入 `parts`** ②另设 **`realPieces` 计数**用于 `L3241` 守卫 ③`joinParts` 加运行时断言 `p && typeof p.s === "string"`（**当场抛错**，不再静默变空）。

**不变量（写入方案）**：*"内容性必须被显式标记并贯穿全链；任何用 `length`／字段真值性判定'有没有内容'的站点，一律视为缺陷。"*
**`kind` 必须贯穿**：`compressUnit`（`L3283`）／`bucketUnits`（`L3316`，**信任声明字段**）／`readUnitCache`（`L3339`）／`mergeUnitCache`（`L3366`）；过滤**必须白名单** `CONTENT_KINDS.has(p.kind)`。

## D-7｜`§3` 九处未定义语义写死

①段列表**只许来自 manifest**（否则孤儿段被 rg 搜到 → 返回过期正文）②归属日 = 该 sid **全部文件 `max(mtime)` 所在日**（整 sid 落一个目录）③**段数有界 + 滚动合并**（建议上限 16）④文件序 = **`mtime` 升序**⑤身份校验不符 → **中止该 sid** + 记 `.build-errors.log`，不静默跳过 ⑥`--show` 扫**全部段但按 `f`+`s` 匹配、扫到即停**；**坐标不存在时显式报"已失效，请改用关键词重搜"，绝不返回邻近/空白**；**以帧号为准**，字节偏移仅辅助 ⑦`--since/--until` 按**事件 `time` 本地时区**，**`--until` 含当天**，另给 `--by-dir` ⑧丢弃计数**落点 = `manifest.json` 的 `dropped:{kind:n}` 逐轮累加** ⑨`A∨B` 判据绑定：A=`data.error != null`、B=`content[].isError===true`（**B 是超集**）

## D-8｜`§3.5` 水位加 API 层约束（工程席）

**★ Node zstd API 不返回"本帧消费了多少字节"** ⇒ 拿不到帧结束偏移 ⇒ 水位**只能是"最后一个已消费帧的起始偏移" `lastFrameOff`**，续跑 `offs.findIndex(o => o > lastFrameOff)`。**写 `+4` 会重复命中同一帧 → 重复行。**
三条约束：①"起始偏移"非"已消费字节数"（后者半帧处二义）②失败/残帧**不得推进偏移**③偏移**检不出"同尺寸原地重写"** ⇒ 需另配 `size`+`mtime`，或**明写检测边界**。
**伪 magic** → null 必须 `continue` 并记入 `badOffsets` 让水位越过（否则水位**永不前进**）。
