# 升级后自检清单（dsh-memory）

> 适用：dsh-memory **v4.5.3 起**（升级后自检功能首次随本版发布）。
> 读者：**用户**（3 步操作）+ **Agent**（收到升级提醒后按本文执行自检）。
> 纪律：自检全程**只读**——不写记忆库、不改配置、不触发迁移；失败也不影响正常使用。

## 一、升级后 3 步

1. **重启 DSH**（必须）。安装/覆盖 `index.js` 后，宿主进程不会热更代码；重启后插件才会执行升级检测。
2. **等首个会话里的提醒**：升级后第一个顶层会话会自动出现一条一次性提示（≤80 字）：
   > 【dsh-memory 升级自检】<旧版本>→<当前版本>：请调用 memory_onboard（action=selfcheck）跑只读自检并报 PASS/FAIL。
   Agent 收到后应**立即调用** `memory_onboard({ action: "selfcheck" })`，把结果如实报给用户。
   用户也可以直接输入 **`/memory-check`** 自己跑（与工具 action 同一实现）。
3. **看结论处理**：
   - 全部 **PASS** ⇒ 无需处理，正常使用。
   - 有 **WARN** ⇒ 非阻塞（如 CLI/headless 无 webServer、库为空、AGENTS.md 缺）；按提示按需处理。
   - 有 **FAIL** ⇒ 按输出里的「修复：」逐条处理（多数是「重跑安装器」或「重启 DSH」），修完重跑 `/memory-check`。

> 升级提醒**全局只注入一次**（`.onboard.json` 的 `upgradeCheck.promptedAt` 落盘），不会每个会话都打扰；
> 新装用户只建立版本基线、不提醒；同版本重启不提醒；降级静默不提醒。

## 二、7 项检查含义

| # | 检查项 | PASS 含义 | 常见 FAIL/WARN 与修复 |
|---|---|---|---|
| 1 | 主题库可用 | 主题库已就绪，报主题数 / 库大小 / backend | FAIL 库未就绪：看启动日志 `[topicdb]` 行，必要时 `/memory-init` 或重跑安装器；WARN flag 关（md 模式） |
| 2 | `memory_search` 可检索 | 工具已注册，且用已知词 `global` 查得到结果 | FAIL 工具未注册：重跑安装器/重启；WARN 库未就绪跳过实查 / 0 命中（索引未建） |
| 3 | `memory_read` 可读 | 能读到一个真实主题且句数 >0 | FAIL 读取异常：看日志；WARN 库空 / 主题为空（先写内容再自检） |
| 4 | `note-stat` 端点 | `GET /dsh-memory/note-stat.json` 返回 200 且 `{ok,topics,sentences}` 结构正确（附耗时） | FAIL 404/结构异常：**升级后未重启**或路由未挂 ⇒ 重启 DSH；仍失败重跑安装器；WARN 无 webServer（CLI/headless 属预期） |
| 5 | `stats.json` 路由 | 路由 200 且响应 JSON 可解析（**纯探活**，证据带字节数/耗时；`topicdb` 有无交给 #4 的 `note-stat.json` 精确判定） | WARN：路由未挂/非 200/JSON 损坏/无 webServer（CLI/headless 属预期）；重启后重跑 |
| 6 | 版本/模板一致 | `index.js` / `version.txt` / `package.json` 三处版本一致，`AGENTS.template.md` 含模板 marker `<!-- dsh-memory-agents-template: v4 -->`；AGENTS 按序查 `~/.dsh/AGENTS.md`（DSH 实际注入源）→ `MEMORY_ROOT/AGENTS.md` → 模板，命中即 PASS 并报路径+字节 | FAIL 三处不一致/模板缺 marker ⇒ **重跑安装器**（`install.ps1 -CheckOnly` 会列 sha 不一致）；WARN 三处候选全缺（安装器会补 `~/.dsh/AGENTS.md`） |
| 7 | `memory_note` 可用 | 工具已注册（**不真写**），报笔记主题数与最近写入时间 | FAIL 工具未注册：重跑安装器/重启；WARN 库未就绪跳过 |

> 说明：第 6 项的 **sha 白名单校验在安装器侧**（`install.ps1 -CheckOnly`），运行期插件看不到
> `install-manifest.json`，故运行期只查「版本三处 + 模板 marker」；需要完整静态体检时：
> `install.ps1 -CheckOnly`。

## 三、FAIL 时怎么办（按类）

- **版本/模板不一致（第 6 项 FAIL）**：最常见原因是「只替换了 `index.js`，没跑安装器」。
  重跑安装命令（`irm <镜像>/install.ps1 | iex`）或 `install.ps1 -CheckOnly` 先看差异；装完**重启 DSH**。
- **端点 404 / 结构异常（第 4 项 FAIL）**：99% 是**升级后没重启**。完全退出 DSH（含托盘/后台进程）再启动。
- **主题库未就绪（第 1 项 FAIL）**：看启动日志 `[topicdb]` 行；若是库文件损坏，按日志提示用备份恢复；
  若是首次使用，先 `/memory-init` 初始化。
- **工具未注册（第 2/7 项 FAIL）**：`tools` 服务不可用或安装不完整 ⇒ 重跑安装器 + 重启。
- **WARN 项**一般不需要处理：CLI/headless 无 Web 服务、库为空、AGENTS.md 待安装器补齐都属预期。

## 四、回滚说明

自检功能本身**无数据库/配置变更**，回滚只需还原代码：

1. 用上一版 `index.js`（及同版本 `memtopic/`、`client/`）覆盖 `~/.dsh/profiles/web/plugins/memory/` 下文件；
2. **重启 DSH**；
3. `.onboard.json` 里新增的 `lastVersion` / `upgradeCheck` 字段是**向后兼容的附加字段**（旧版读到会忽略），
   可保留也可手工删掉这两个键；删除只会让下次升级重新检测一次，不影响记忆库数据。

> 卸载/重装记忆插件不涉及记忆库本身（`~/.dsh/memory/`）；如需完全重置记忆库请另行备份后操作。
